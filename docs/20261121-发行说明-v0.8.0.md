# 神算子 v0.8.0（第十七个可部署版本）· 发行说明

> 日期：2026-11-21 · 数据格式：`schema v8`（**不需要迁移**，老数据直接打开）
> 上一版：`v0.7.9+16`（第十六个可部署版本）
>
> 这一版没有新业务功能。做的是三件「用户天天遇到、我们一直欠着」的事：
> **① 点进页面不再卡住界面**；**② 窗口被拖窄时不再挤爆排版**；**③ 备份与恢复不再冻界面、不再空等**。
> 顺带把库存页的「缺货榜」和「在店可售」补齐，并把主机的网络绑定改得更诚实。

---

## 一、三个页面不再「点下去就卡住」（本版最大的一项）

**以前的症状**：点左侧「概览」，界面**整窗冻住** —— 慢盘（虚拟机 / 机械盘 / 网盘同步目录）上
实测 **7.08 秒**，期间鼠标点不动、其它页也切不走；库存页与单据页同理（分别约 4.6–7.7 秒、0.9 秒）。

**现在**：

| 以前 | 现在 |
|---|---|
| 点进去 → 整窗僵住 → 数据突然全出来 | 点进去 → **马上看到页面框架与「正在统计…」** → 数字几秒后填进来 |
| 等待期间点哪儿都没反应 | 等待期间**可以照常切到别的页、点别的按钮**（查询在后台线程跑） |
| 查询读的就是唯一那条库连接 | 后台**另开一条只读连接**，并且**几条查询在同一个只读事务里**完成（同一页各卡片看到的是同一时刻的数） |

三条硬保证（不是优化项，是正确性）：

1. **只读**：后台连接不允许写库（连「设个参数」这种写都被禁止）；
2. **同一快照**：一页几张卡不会出现「今日营收是新数、应收是旧数」；
3. **过期结果丢弃**：换库 / 重连 / 手机镜像切换之后，之前那趟算完的结果**不会**盖掉新状态。

> 界面上等待态的提示只是一行字 + 一个静态沙漏，**没有转圈动画** ——
> 中老年用户会把转圈的灰格子当成「加载失败」，静态反而更让人安心。

## 二、切走再切回来，不再「先闪一下空壳」

**以前的症状**：切到别的页再切回概览，会先画一帧「正在统计…」再画数字，
真机上约 0.3 秒、虚拟机上约 1 秒，一闪而过但看得见。

**现在**：切回来**直接用上次算好的数字先把画面填上**，同时在后台照旧重算，
并在页面上多一行小字「**正在刷新…（先显示上次的数字，算完会更新）**」。

- 数字**仍然是每次重新查的** —— 不会因为「有缓存」就停止更新；
- 单据页的缓存**按筛选条件区分**：换了筛选再进来，绝不会拿「上次那个筛选」的行冒充；
- 那行提示是**必须**的：不告诉用户「还在算」，他会把旧数字当成最终结果。

## 三、窗口不能再拖成一条缝（480 × 360）

窗口现在**最小 480 × 360**（按系统缩放折算）。低于这个宽度时，每一页都会开始局部溢出：
按钮被挤出屏幕、金额被压成两行、卡片内容竖排。与其给每页各写一套「极窄兜底」，
不如**不让窗口进到那一档**（做法参考 LocalSend）。

> 相关：左侧导航在很窄时仍会自动退成「图标 + 悬停提示」，这条保留（480 之内用得上）。

## 四、窄窗口的溢出，全线清掉

| 位置 | 以前 | 现在 |
|---|---|---|
| 账户页（长金额「¥ 100,000.00」） | 名字被挤成一字一行，还顶出黄黑条纹 | 窄了改三行：名字 / 金额 / 按钮 |
| 往来方页「总应收 / 总应付」 | 金额被拆成「¥390.」+「00」 | 窄了上下两行 |
| 商品页工具条与商品行 | 「新增商品」被切掉（溢出 144 px） | 搜索独占一行，金额与按钮自动换行 |
| 库存页压货榜摘要 | 变成竖排的「椭圆」 | 正常换行 |
| 销售开单页 / 月对比卡 | 金额被裁 | 放不下就换行 |
| 导航分割线 | 对比度 1.63（几乎看不见） | **4.30**（WCAG AA 通过） |

这些位置都留了**回归护栏**（窄到 264 / 160 逻辑像素的自动测试），以后改版不会又冒出来。

## 五、备份与恢复：不冻界面、不空等、备份本身更可靠

- **「找回数据」不再冻住界面**：接回备份、体检都搬到后台线程（真机上以前整窗停住）；
- **恢复对话框改成「清单先行，点谁查谁」**：以前要等 7 份备份**全部**检查完（约 17 分钟）才能选，
  现在列出清单，你点哪份就只查哪份；
- **备份改用一致的数据库快照**（`VACUUM INTO` + 只读自检，失败自动删半成品）——
  以前边用边备份可能拷到「一半」的文件；
- **手机导出**：先做两个库的一致快照，再把未同步队列清单一起带走；失败时**阻断分享**
  （以前会照常分享一个「空壳」，用户以为单带走了其实没带）；
- 体检不通过时，行状态会**如实回写**成「不可用」并给出结论，不再显示一个说不清的「可用」。

## 六、库存页：加「缺货榜」与「在店可售」

- **在店可售 = 账面库存 − 送货在途**，主列显示它；**低于 0 标红**（超卖），
  **≤ 安全库存标橙**（该补货）；
- **缺货榜**：一眼看出「哪些该补、超卖几个」，手机端还会把「未同步的影响」算进去
  （与库存页同一口径，不再出现「两页说法不同」）；
- 概览页的缺货提示与库存榜**共用一次扫描**，不多花时间。

## 七、主机（Windows）网络行为更诚实

- 同步服务**只绑局域网网卡**（不再监听所有网卡）；
- 「换地址」现在是**真的换绑定**（并复用原端口），不只是改个显示；
- **换了网卡 / 换了 WiFi** 时会明确提示「这台电脑的地址变了，手机那边要重新连」——
  以前是手机一直连不上、主机这边却安静无声。

## 八、修掉的两个真 bug

| 级别 | 症状 | 现在 |
|---|---|---|
| **P0** | 「期初录入 / 重新清点」在部分路径上**没落库**，界面却显示成功 | 已修；并有回归测试盯住 |
| **P1** | 开单时商品名自动补全**第一次输入不弹**候选（第二次才弹） | 已修 |

## 九、怎么验证这一版（4 步）

1. **启动**：打开软件 → 概览页应该**立刻出现页面框架**，数字随后填进来，期间可以点左侧换页。
2. **切页**：切到「单据」再切回「概览」→ 应**直接看到数字**，页面上有一行「正在刷新…」，很快消失。
3. **拖窗口**：把窗口往窄拖 → 到某一宽度就**拖不动了**（约 480 逻辑像素），期间不出现黄黑条纹。
4. **备份**：设置 → 立即备份 → 得到一份文件；改成与现在不同的数据后，用「找回数据」点它，
   应能看到「清单 → 点一份 → 检查」的流程，而不是整窗停住。

## 十一、已知限制（照实写）

- **切页仍会重新查一次库**：本版只是让它「先把上次的数字画出来、不再闪」，
  并没有跳过查询（跳过查询需要一套「数据什么时候失效」的机制，漏一处就是「数字不更新」，
  风险大于收益，**明确不做**）。慢盘上切回概览仍会有一次后台重算，只是看不见了。
- **冷盘上首次进入仍然慢**：概览一次要碰 **157.92 MB**、在途查询要 **84.4 MB**，
  慢盘（约 11–22 MB/s）上就是几秒 —— 本版解决的是「不冻界面」，不是「读得更快」。
- **手机离线很久时的一种漏状态**：离线期间电脑上改动超过一页（200 张）单据时，
  最旧的那几张的「收款 / 签收」状态可能补不回来。已定位并留了可复现的测试，
  **修它要改同步协议**，排在下个版本评估。
- **单据搜索的「共 N 条」在冷盘上约 2.4 秒**：已记录，未修（不影响正确性）。
- **移动端覆盖**：仍是「单机 + 一台手机」链路；多手机并发推送未测。

## 十二、升级须知

1. **不需要迁移数据**：schema 仍是 v8，老库直接打开。
2. **建议升级前先点一次「立即备份」**（任何版本升级都建议这么做）。
3. 窗口最小尺寸、切页先画旧数字这两条**不需要设置**，升级后即生效。
4. 如果你更喜欢「切页永远等最新数字、宁可多等一下」，目前**没有开关**（这是有意的：
   多一个开关就多一种状态要排查）。
