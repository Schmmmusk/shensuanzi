# 神算子 v0.7.3（第十一个可部署版本）· 预览发行说明

> 日期：2026-11-01 · 数据格式：`schema v7`（**不需要迁移**）
> 上一版：`v0.7.1+10`（第十个可部署版本）
>
> 这一版没有新功能，全部是**可靠性收口**：把联调 #0 / #1 拖了很久的两件事做完，
> 并顺手补上了它们暴露出来的三个「用户会踩、但我们一直没挡」的洞。

---

## 一、手机端：本机数据坏了不再拦人（联调 #0）

**以前的症状**：手机上 `data/shensuanzi.db` 一坏，App 直接停在「数据文件暂时打不开」——
**尽管镜像完好、80 张单据都在里面**。

现在按损坏程度分三个状态处理：

| 状态 | 判定 | 用户看到 |
|---|---|---|
| 1 · 旧主库打不开 | `openMirror()` 正常 | 照常进主界面，**只读**（开单 / 改资料关闭），顶部常驻说明 + 「怎么办」 |
| 2 · 镜像能开但数据不对 | `PRAGMA quick_check` 不过 | 「自检没通过（文件内部有坏页）」+ 修复入口 |
| 3 · 镜像文件打不开 | `openMirror()` 抛 | 「手机上的数据文件打不开」+ 重试 / **修复本机数据副本** |

**「修复本机数据副本」做什么**（状态 2 / 3 共用）：

1. 把原文件（`.db` + `-wal` + `-shm`）**改名留档**，一个字节不删；
2. 在**副本**上抢救 `sync_queue`（**带上 `-wal`** —— 没 checkpoint 的最新单据就在里面）；
3. 把抢回来的条目写回新副本（`sent` 降级成 `pending` 重推，`failed` 保持死信）；
4. 建一份新镜像，从电脑**全量重拉**；
5. 落一份**抢救清单**（条数 / 明细 / 状态 / 留档路径），**抢不回来的如实写出来**。

> 「读不出来」与「本来就没有」是两件事 —— 文件认不出来时会明说
> 「里面有没有没传上去的单，现在无法确认」，**不许**说成「没有未传的单」。

## 二、手机端：重启后不用再重新配对（提案 57）

**以前的症状**：主机只存令牌哈希 ⇒ 重启后画不出二维码 ⇒ 用户只能点「重新生成」
⇒ **轮换令牌 ⇒ 所有手机掉线重扫**。每天开机一次，就每天断一次。

现在令牌明文用 **Windows DPAPI（当前用户作用域）** 加密后存进 `host.json` 的
`token_protected`（`token_hash` 保留、校验逻辑一行没改）：

- 附加熵 = `sha256(host_id)` ⇒ 密文挪到别的 `host.json` 里解不出来；
- 解出来还要过第三关：**`sha256(明文) == token_hash`**，不一致按不可信处理（不画码、不改哈希）；
- 换 Windows 用户 / 换电脑 / 密文损坏 ⇒ 解不开 ⇒ 界面**说清原因**再要求重新生成一次；
- **绝不静默轮换令牌**（那会把所有手机踢下线）。

### ⚠️ 升级后的一次性成本（务必知道）

老 `host.json` 里**只有哈希，明文不可反推**。所以升级后：

1. 第一次要**手动点一次「重新生成配对码」**（那一刻才写入密文）；
2. 那一次**手机会需要重扫一次**；
3. 此后同一台 Windows 用户、同一台电脑，重启不再需要配对。

## 三、主机端：低权限启动的自检 + **真只读**（联调 #1 结案）

**根因**（查了两天）：仓库目录带了 **Low 完整性标签**，构建出的 exe 继承它 ⇒
Windows 以 Low 完整性启动 ⇒ 写不了任何 Medium 目录（`%APPDATA%` / `%LOCALAPPDATA%` /
数据目录）⇒ 每次写都是 `errno 5`。**读一切正常**，所以看起来像「软件偶尔抽风」。

现在：

- 启动时读进程完整性级别（`OpenProcessToken` + `GetTokenInformation`），写进日志；
- **Low / Untrusted ⇒ 真只读**：开单三页、库存清点、商品新增/编辑/停用、收付款、退货
  **全部从代码路径上关掉**（不只是把按钮画灰）；
- **Unknown ⇒ 不禁用**（检测失败不能擅自废掉功能），只记日志；
- 弹一次人话提示：说清「什么都存不下来」、程序没坏账目没丢、
  三条自救路径（**复制到别的位置** / 右键属性勾「解除锁定」 / 报「进程完整性 = Low」），
  并警告「修好之前别在这个窗口里录单」。

## 四、主机端：手机推单后列表立刻刷新

**以前的症状**：手机推单成功、主机显示「已同步」，单据页却不变化，切走再切回才刷新
（库存页倒是新的 —— 因为它每次 build 现查）。

根因：单据 / 商品 / 概览三页把查询结果**缓存在 State 里**（性能裁定：26 万单上重查 ≈227 ms），
父级 `setState` 不会让它重查。现在壳把「落库版本号」传下去，三页在 `didUpdateWidget` 里
**只重查、不动筛选与滚动位置**。

## 五、顺手修的几处「英文漏上界面」

- 同步失败不再弹 `连接主机失败（Connection reset by peer）`，
  改成「连接被中途断开了 —— 请确认电脑上的神算子还开着…」，原文进日志；
- 镜像自检的 `malformed` 翻成「文件内部有坏页」；
- 抢救清单是纯文本，去掉了 Markdown 星号。

## 六、怎么验证这一版（3 步）

1. **手机**：打开 App → 应正常进主界面；「我的 → 设置」里能看到同步状态。
2. **配对**：主机开服务 → 手机扫码 → 拉一次数据 → 开一张单 → 推上去。
3. **重启**：关掉主机、重开 → 设置 → 多设备同步 → 打开 → **二维码应与上次一模一样**，
   手机**不用重扫**（这是本版最核心的一条）。

## 八、已知限制

- **本版是预览**：真机只覆盖到「单机 + 一台手机」这一条链路，多手机并发推送未测；
- 低完整性自检只覆盖**启动时**的进程标签 —— 运行中被别的工具改了标签不会实时发现；
- 备份与导出在低权限下仍会失败（会有错误提示，但不会预先置灰）；
- 提案 56 的 `schema v8`（把主机身份搬进库）按裁定**暂缓**，本版未动。
