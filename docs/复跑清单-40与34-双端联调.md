# 复跑清单：#40 + #34① + 双端联调（2026-10-19）

> 用法：照着点，**每条都有「期望」和「失败时抓什么」**。全部通过 ⇒ 可以打 0.6.1 给家人装。
> 配套：`docs/desktop_acceptance.md`（总验收）· 台账 §CV·六十八（#40）/ §CV·六十九（#34①）。
> 时间预算：**A + B 约 15 分钟**（桌面）· **C 约 2–3 小时**（双端，建议分两次做）。

---

## A. #40 复跑（桌面，10 分钟）

### A① 同名往来方：四个入口都要有话说

| 步骤 | 期望 |
|---|---|
| **A1 采购页**：采购入库 → 点供应商栏 → 输入一个**已有客户**的名字（如「李姐」）→ **点一下别处让输入框失焦** | 出现**橙字**：「已有同名客户「李姐」—— 保存后会加上「供应商」身份，不会新建第二条。」 |
| 接着点「新建供应商（用上面的名称）」 | 顶部提示：「已有往来方「李姐」，已加「供应商」身份（不会新建第二条）」，并且**选中**了李姐 |
| 去「往来方」页看 | **只有一条李姐**，角色是「客户、供应商」（不是两条） |
| **A2 销售页**：同上，用一个**已有供应商**的名字 | 提示「已加「客户」身份」 |
| **A3 送货页**：同上 | 同 A2 |
| **A4 往来方页**：「新建往来方」→ 输入已有名字 → 失焦 | 橙字出现；保存后弹提示；**列表不新增第二条** |
| **A5 停用档复活**：先把某人**停用** → 再用他的名字建 | 橙字里应出现「**（原来是停用的）**」；保存后他恢复启用 |

**失败判据**（任一即为 bug）：出现两条同名 / 四个入口里有一个**完全没有提示** / 提示了但实际新建了第二条。

**失败时抓**：往来方页截图（看是否两条）+ 该入口的截图。

### A② 「显示已停用」两个开关

| 步骤 | 期望 |
|---|---|
| **B1 往来方页**：找一个**停用但还欠钱**的 | 默认就**在列表里**（标「已停用 · 账未结清」） |
| 勾上「显示全部（含无欠款的停用档）」 | 停用且**不欠钱**的也冒出来；取消勾选 ⇒ 它们消失 |
| **B2 账户页**：停用一个**还有余额**的账户 | **不勾开关也仍然能看到它**，余额显示正常 |
| 勾上「显示已停用的账户」 | 余额为 0 的停用账户也出现 |

**失败判据**：停用但**有余额**的账户从列表消失 —— 这是「幽灵账」，最严重。

### A③ 差额前置（采购 / 销售各一次）

| 步骤 | 期望 |
|---|---|
| **C1 采购**：不选供应商、不填付款、有金额 → 保存 | 第一条错误是「**这一单还差 ¥X 没付。**散采要当场结清：要么现在把款填上，要么选一个供应商把欠款记到名下。」 |
| **C2 销售**：不选客户，同上 | 「这一单还差 ¥X **没收到**。散客要当场结清：…」 |
| 边界：填**多于**应收 | **不该报**（多出的是找零） |

**失败判据**：差额不在第一句 / 数字和单据合计对不上。

### A④ 「顾客给了」不记账的指路

| 步骤 | 期望 |
|---|---|
| **D1** 销售：合计 ¥50、现金账户、「顾客给了」填 `100`、**收款框留空** | 收款区出现橙字：「『顾客给了』只用来算找零，不会记账。这 ¥100.00 要填在收款框里才会记进去；现在保存会**整单赊账 ¥50.00**。」 |
| **D2** 再把收款框填 `50` | 橙字**消失** |
| **D3** 保存后看单据详情「已收」 | 等于收款框的 50（「顾客给了」的 100 **没有**被记账） |

**失败判据**：提示不出现 / 填了收款框提示还在 / 已收变成 100（那就记账了，属严重）。

### A⑤ 设置页「最近连接」

| 步骤 | 期望 |
|---|---|
| 主机服务开着、手机连过一次后，停在设置页 | 「最近连接」时间会**自己更新**（不用切页） |

> 这条要配合 C 段做；单独测时可能看不出差别。

## B. #34① 超大档溢出（桌面，5 分钟）

| 步骤 | 期望 |
|---|---|
| **E1** 设置 → 字号调到 **超大**；（可选）Windows 显示缩放也调到 **200%** | — |
| **E2** 往来方 → 点进任意一个人 → **流水**页 | — |
| **E3** 看每一行 | 左：单号 / 「类型 · 日期」；右：金额**完整**。**没有黄黑溢出条纹** |
| **E4** 把窗口从最大化拖到较窄（但还能用） | 仍无条纹；挤的时候是**单号变省略号**，**金额不许被截** |
| **E5** 字号调回标准 | 单号、类型·日期、金额三样都在 |

**失败判据**：黄黑条纹 / 金额变成「¥26…」/ 金额被挤到第二行。

### B2 同款溢出（2026-10-19 你已抓出两处，都修了，请顺带复验）

| 页 | 怎么造 | 期望 |
|---|---|---|
| **账户** | 超大档 + 窗口与别的软件**均分**（内容区约 520 宽）→ 看「微信收款账户」那行 | 名字**完整**一行，第二行「微信 · 期初 ¥…」；**没有条纹** |
| **往来方** | 同上 → 找一个**双角色**的往来方（客户 + 供应商） | 「供应商 / 客户」**横排一行**（不是竖排单字）；停用标记在**下一行**；没有条纹 |

> 这两处的共同根因是「名字和标签抢同一行、谁都不让位」—— 修法是**主字段独占一行**。

### B3 导航列宽度（2026-10-19 你抓的「工作区被挤没」）

| 步骤 | 期望 |
|---|---|
| 系统缩放 **200%** + 应用 **超大** + 窗口与别的软件**分屏**（内容区约 480 宽） | 左侧导航**不超过窗口的 40%**，右侧工作区能正常看、能操作 |
| 把窗口拉宽 | 导航**按原来的宽度**（不跟着窗口无限变宽） |
| 窄到 150 宽（极端） | 导航退到 60（仅图标）—— 这是兜底，不是常态 |

> 判据一句话：**导航不许把工作区挤成一条缝**。

### B4 窄窗口下的流水卡片（2026-10-19 你抓的「金额被挤到卡片外」）

| 步骤 | 期望 |
|---|---|
| 把窗口**拖窄**（< 600 宽，走窄卡片）+ 应用**超大** → 往来方 → 进某人流水 | 金额「欠款 +¥100.00」**整块在卡片里**；放不下时**换到下一行**，不许跑到卡片外 |

> 判据一句话：**金额可以换行，不可以出界**。

**失败时抓**：窗口尺寸（宽×高）+ 字号档位 + 截图。这组信息能直接定位。

## C. 双端联调（桌面主机 + 安卓，2–3 小时）

### C0 准备（10 分钟）

1. 电脑和手机连**同一个 Wi-Fi**；
2. 桌面：设置 → 主机服务 → **打开**，记下**端口**、让二维码显示出来；
3. 手机：装 release 包（`--target-platform android-arm,android-arm64`），扫码配对；
4. 桌面**先停在「单据」页**（不要停在开单页 —— C1 要验自动刷新）。

### C1 手机推 → 桌面自动刷新（#40⑤ 的核心，5 分钟）

1. 手机开一张销售（选客户、收一部分款）→ 保存；
2. **桌面什么都不做**，等 1–3 秒；
3. 期望：单据列表**自动**出现这张单（不用切页、不用点刷新）；
4. 再去概览页：今日笔数 / 金额已更新。

**失败判据**：
- 必须切页才看到 ⇒ 回调没接上；
- 桌面列表**每几秒自己闪一下** ⇒ 把「任何认证请求」当成信号了（不该有，纯 pull 不能触发重建）。

### C2 开单页不许被打断（5 分钟）

1. 桌面停在**销售开单**，选好商品、填好数量，**光标停在金额框**；
2. 手机上再推一张单；
3. 期望：桌面开单页**不刷新**，输入内容还在、焦点没跑、没有键盘弹起；
4. 切到「单据」页 ⇒ 那张单在。

**失败判据**：输入被清空 / 焦点跳走 / 页面闪一下。

### C3 各类单据各走一条（1–1.5 小时）

每类**手机开、桌面验**：

| 单据 | 手机操作 | 桌面要验 |
|---|---|---|
| 采购 | 选供应商、部分付款 | 列表有、详情「已付/未付」对、库存增加 |
| 送货 | 开送货单（在途）→ 手机**签收** | 状态变「已签收」、库存按签收走 |
| 退货 | 对某张销售做**部分退货** | 主单行出现「已退 N 次 ¥X」、详情「退货记录」在最上面、能点开退货单 |
| 收款 | 对欠款单**收款** | 主单行「已收 N 笔」、未收额减少、**收款单不再单独占一行** |
| 商品建档 | 手机新建一个商品 | 桌面商品页出现、编码正确 |

> 「退货 / 收款不单独占一行」是 #26③ 的成果 —— 如果又看到它们单独成行，说明聚合没生效。

### C4 断网与补传（15 分钟）

1. 手机关 Wi-Fi → 开一张单 → 保存；
2. 期望：手机标「待同步」；桌面**没有**这张单；
3. 手机恢复 Wi-Fi + **切回前台** → 自动补传；
4. 桌面出现这张单。

**顺手记录**（这是 #24 要改的，本批不改）：失败时手机上到底显示了什么字，原样抄下来。

### C5 任何异常都按这个格式记

```
时间：2026-10-19 14:32
设备：桌面 Win11 1920×1080 / 字号超大 2.0 ｜ 手机 红米 Note 12
单号：XS20261019-003
现象：单据列表没自动出现，切页后才看到
截图：<附>
桌面日志：<设置 → 关于 → 日志 的最后 50 行>
```

## F. 2026-10-20 三处订正（复验 5 分钟）

| 步骤 | 期望 |
|---|---|
| **F1 桌面概览页** | 顺序：标题「概览」→ 店名 → **你的数据在** → **从这里开始** → 才轮到 `今日销售 / 要留心 / 要开工` 三张卡；卡片与上文之间有间距，不贴边 |
| **F2 手机概览页** | 三卡在**最底部**竖排；每张卡之间、以及卡片块与上文**都有 10–20px 间距**，没有「边缘叠在一起」（若仍有，请补截图） |
| **F3 帮助页** | 开头那句是「每一步在**导航栏**里都有常驻入口」—— 不出现「左侧」 |
| **F4 用户手册（双端）** | 字号调到**特大 / 超大** → 每章左上角的**数字标号完整可见**（不被方框裁掉）、方框跟着变高；常规档下仍是原来的小方块 |

## G. 出包前（2026-10-20 起，每发布一次走一遍）

| 步骤 | 判据 |
|---|---|
| **G1 出包** | `flutter build apk --release --target-platform android-arm,android-arm64`（一个文件、不自适应拆分） |
| **G2 验签** | `apksigner verify --print-certs` 的 DN 必须是 `CN=Conroe, OU=Shensuanzi`；**出现 `CN=Android Debug` 就是签错，不可分发** |
| **G3 换机升级** | 手机若装过 debug 包 ⇒ 签名不一致装不上；**先确认离线队列已同步**（三态条「已同步」+ 桌面核对这几天手机开的单），**再卸载重装** |

> 为什么 G3 要强调同步：卸载会丢掉手机本地还没推给电脑的单（队列），镜像能重建、队列不能。
