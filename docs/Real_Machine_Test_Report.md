## 其余已发现漏洞

1. **在开单页面，选中一个支持两种单位的商品及其最小售卖单位，输入一个超出库存限制范围的数量后，切换到另外一个计数单位，当前商品明细行不提示负库存。该现象仅存在于上一单开完还没同步、马上要开下一单同一商品的情况。**后续应当对手机端的同步策略加以调整。
2. Android 渲染问题：
```markdown
    在超大缩放设置下，开单--送货页面底部的“取消”“保存”两个按钮没有和另外两个页面一样换行，而是并成一行，同时在保存按钮上发现了**渲染超限问题**（有提醒）。
    同上设置，在帮助--用户手册页面中，所有使用字符渲染的编号全部发生了溢出（没有渲染超限提醒），这一问题同时存在于pc版和Android版。注意到帮助页面“四步上手”部分编号采用emoji，用户手册页面是否也可以采取同样编号方式？
```
3. 老生常谈，这里再作**提醒**：对于中老年用户，手机显然比电脑更加易用。应当尽早开放手机版上几处“这一步在电脑上做”的限制，适配中老年用户少有会用电脑、着急开单却不会用电脑键盘打字的场景。
4. 底层设计与展示实现问题：神算子的设计原则是“只相信流水”，因而单据页面所有单据排序都遵守这一原则进行按时间排序。但对用户而言（尤其是中老年用户），这样做**极大地提升了寻找所需单据的成本（对我一个年轻人亦是如此）**。应当考虑：能否将同一张单子下发生的各种行为（如退货、赊账后结账等）在界面上聚合为一张单子，便于用户查询？
5. 界面设计问题：对于库存、往来方、账户等页面，能否提供对应的入口，方便用户查询自创建以来的变动？
6. 概览页面：该页面不应该只有数据存储、界面导航的相关提示，还应该考虑加入单据、库存、往来方、账户等简要图表或导航（只展示近期、欠款等）
