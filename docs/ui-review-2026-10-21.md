## 二、当前页面值得改进的地方

### 2.1 P0——会让用户的数据/设置「看起来坏了」

#### P0-1 设置页配置快照陈旧：迁移后改任何设置，数据位置被写回旧路径

- `settings_page.dart:121` `late AppConfig _current = widget.config;` —— 只在 State 首次创建时求值，
  **没有 `didUpdateWidget` 回灌**。
- 迁移成功后宿主写的是新路径：`app.dart:1119-1121`（`_config.copyWith(dataDirectory: target)` + `save` + `setState`）。
- 但设置页下一次 `_apply` 用的仍是被冻结的 `_current`：
  `settings_page.dart:177-181`（`save(newConfig)` + `onChanged(newConfig)`）、
  `:190-196`（改店名）、`:247-253`（调缩放）、`:266-272`（恢复默认大小）。
- 后果链：① 迁移完成后设置页**仍然显示旧路径**（`:314-319` 读 `_current.dataDirectory`）；
  ② 用户随手调个字号或改店名 ⇒ 旧路径写进 `config.json` + `onChanged` 把宿主 `_config` 也拉回旧值
  （`app.dart:1771-1774`）；③ **下次启动打开旧目录**。迁移是「拷贝不删除」，
  所以用户看到的是「搬到新位置以后，最近几天开的单全没了」。
- 建议：`didUpdateWidget` 里 `_current = widget.config`；`_apply` 基于 `widget.config.copyWith(...)`
  而不是 `_current`；迁移回调完成后再 `setState` 一次。凡是「页面持有一份 config 副本」的 widget 都要这条。

#### P0-2 三个流水页把字号静默夹到 115%，覆盖用户在设置里选的档位

- `stock_flow_page.dart:102-106`、`account_flow_page.dart:98-101`、`party_flow_page.dart:91-94`：
  三处逐字复制的 `MediaQuery.withClampedTextScaling(maxScaleFactor: 1.15)`。
- 触发条件 `constraints.maxWidth < 600`（`stock_flow_page.dart:53`）——**手机壳恒成立**，
  桌面分屏或 200% 系统缩放时也恒成立（1920 屏在 200% 下只有 960 逻辑像素）。
- 也就是说：用户在设置里选「超大 200%」**正是因为看不清**，进这三页却被打回 115%（连默认 125% 都被削）。
  违反 `ui_principles.md` §三「缩放放设置里，全部相对单位」，而且用户**不知道**自己被降级了。
- 建议：删掉 clamp。窄屏靠本页已有的行重排解决（`stock_flow_page.dart:87-89` 的
  `_NarrowFlowCard` / `_WideFlowTile` 就是为此写的）；确实放不下时用 `Wrap` + 允许两行，
  不要动用户的字号。

### 2.4 P1——可用性断点（用户看不到出路，或看不到能点）

1. **保存失败只标红，不告知、不定位** —— 四个提交页一致：`sale_page.dart:551-559`、
   `purchase_page.dart:409-416`、`delivery_page.dart:375-383`、`return_page.dart:320-326`。
   典型触发：散客 + 有欠款 → 错误挂在**页顶**客户框（`sale_page.dart:845`），而用户的视线在**页底**保存按钮。
   机制其实已有（`keyboard_reveal.dart:52-70` 的 `ensureVisible`），只是没用在错误上。
   **建议统一**：保存失败 → 滚到第一个出错字段 + 在按钮旁给一句「还有 2 处要填，已跳到第 1 处」。
2. **退货页的退款区错误永远不出现在它旁边**：`_invalid.summary` 只印在页顶（`return_page.dart:320-326`），
   而退款账户 / 金额在页底且**都没有 `errorText`**（`:507-512`、`:534-548`）。
3. **退货页没有「放弃确认」**：三张开单页都有 `PopScope`（`sale_page.dart:771-787` 等），退货页没有
   （`return_page.dart:300-350`）——填了数量按返回直接丢。且两条前置校验走 SnackBar（`:205-216`），几秒消失。
4. **概览页在空库时一个可点的按钮都没有**：经营速览整块（含「要开工？」入口卡）被
   `hasAnyDocument()` 门控（`overview_page.dart:244-247`），入口卡在其中（`:324-357`）。
   注释只论证了「经营数字空库不显示」，**快捷入口是被顺带藏掉的** —— 而空库恰恰最需要它。
   建议：把「要开工？」移出门控，空库再加一句「第一次用？先到『商品』页建一个商品」+ 一个按钮。
5. **概览页承诺了「数据在哪」，但没有「打开文件夹」**：`overview_page.dart:185-188` 只是
   `SelectableText` 一条路径；设置页同一路径带「打开文件夹」按钮（`settings_page.dart:451`、`:199-206`）。
   同时 `ui_principles.md:258-260` 要求的那句核心承诺（**「在你自己电脑上，不会上传」**）页面上没有。
6. **签收不可逆、无确认**：`document_detail_page.dart:625-633` 一点即从 `in_transit` 变 `delivered`，
   无二次确认；反向只能走退货。建议照退货页（`return_page.dart:271-290`）加一句
   「确认签收？签收后不能再改回在途，只能走退货。」
7. **核销对话框在没有资金账户时主按钮仍可点**：`settlement_dialog.dart:313-318`，判定藏在
   `_confirm` 里（`:169-172`）；三张开单页是「死局预防」（无账户就禁用「全款」+ 橙色指路，
   `sale_page.dart:1001-1028`）。同一件事两套体验。
8. **列表上限静默**：商品页 `list()` 默认 `limit: 200`（`product_service.dart:48`），超了不提示，
   而「共 N 种」（`products_page.dart:187-193`）印的是**截断后**的条数 —— 等于向用户保证了一个错误的总数。
   单据页至少写了 200 条上限（`documents_page.dart:442`），但只在「全部」档写，其余档同样截断却不说。
9. **手机端「单据」没有入口，手册却全指向它**：手机固定 5 tab 概览/开单/库存/往来/我的
   （`mobile_shell.dart:39-45`），`DocumentsPage` 没有任何入口；而手册的送货 / 退货 / 收款三章
   全写「到『单据』里打开那张单」（`manual_content.dart:243-252`、`:258-272`、`:486-504`）。
   反例（做对了的）：`delivery_page.dart:772-779` 已为手机改写了指路 —— 这个做法要推广。
10. **手机底部导航标签被框架夹在 1.3×**：`NavigationBar` 内部 `MediaQuery.withClampedTextScaling`
    （Flutter SDK `material/navigation_bar.dart:506-511`），所以 200% 档下正文 28px、五个标签仍约 1.3×。
    最该看清的一行反而最看不清。建议给 label 包一层带应用 `textScaler` 的 `MediaQuery`（SDK 注释里的 opt-out 方式）。

### 2.5 P2——打磨项（按主题合并）

**缩放与尺寸（根因见 §三·A）**
- `ui_principles.md:116` 要求「尺寸全部用相对单位」，实际只有字号是相对的：导航项 48 固定 + 图标 20 固定
  （`navigation.dart:86`、`app_shell.dart:665-678`）；行内竖向 padding 全是常量
  （`stock_page.dart:510`、`products_page.dart:247`、`documents_page.dart:566`、`parties_page.dart:404`、
  `account_page.dart:273`）⇒ 100% 档行高 38–45px，**低于规范 48px**。
- 固定像素宽度：商品页售价/进价 96（`products_page.dart:317-332`）、小计 96（`entry_fields_row.dart:37/57`）、
  「顾客给了」120（`sale_page.dart:1120-1122`）、详情页标签 72（`document_detail_page.dart:967-992`）、
  表单弹窗 560（`product_form_dialog.dart:286-287`）、核销弹窗 420（`settlement_dialog.dart:212`）。
  200% 档「¥1,234.00」会被折成两三行。
- 断点不乘缩放：`sale_page.dart:1155` 写死 `< 480`、流水页写死 `< 600`（`stock_flow_page.dart:53`），
  而明细行断点已经会随字号放宽（`entry_layout.dart:27-33`）—— **同一页两套口径**。
- 概览三卡横排无断点：`overview_page.dart:372-381` 一律三列各 1/3，分屏到 900px 时每卡约 280px。
- 启动错误页不可滚动：`app.dart:1815-1844` 是 `Center > ConstrainedBox > Column`，
  而「库文件不见了」正文有 7 行（`:662-671`）—— 这是首启/坏库时**唯一的一屏**，
  200% 下会裁字、把按钮顶出屏幕。首启对话框已经为同一问题加过滚动（`data_directory_dialog.dart:140-151`），
  这里没跟上。扫码页同理（`pairing_scan_page.dart:214-247`）。

**提示形态与颜色**
- 橙色 `0xFFB45309` 在全仓出现 **27 处**（3 处私有常量定义：`overview_page.dart:23`、
  `product_form_dialog.dart:52`、`host_service_section.dart:38`；其余 24 处是字面量），
  另有 `0xFF9A5B00`、`0xFF92400E` 两个近似色（`data_directory_dialog.dart:253`、`help_page.dart:90`）
  —— 改深一档必漏一片。建议提到与 `AppTypography` 同层的纯 Dart 常量。
- **`Colors.red` 对比度不达标**：`overview_page.dart:317` 负库存告警用 `Colors.red`（#F44336）在
  `#FAFAFA` 背景上约 **3.5:1**，低于 §二「次要文字 ≥4.5:1」。换成 `colorScheme.error`（约 6.2:1）即可，
  且与全仓其它错误色统一。
- 「不拦人的告知」有三套外观：带图标橙行（`sale_page.dart:1086-1098`）、无图标橙字
  （`entry_unit_hints.dart:45-56`）、带边框橙盒（`settlement_dialog.dart:324-343`）。建议统一为「图标 + 橙字」一种。
- 点击区 < 44px 的常驻控件：商品单位 chips（M3 `ActionChip` 默认高约 32px，
  `product_form_dialog.dart:349/356`）、库存页成本口径 ⓘ 约 22px 高（`stock_page.dart:582-604`）。

**可点性与线索**
- 库存页行可点开流水（`stock_page.dart:420-424`），但整页没有一句「点一行看流水」、行内也没有箭头

## 三、面向中老年用户（40–60 岁）的改进建议

前两节是「哪里不对」，本节是「怎么做才对」。十条原则，每条给落点与可抄的样板。

### A. 把「缩放」当布局问题，不是字号问题（**最高优先级**）

现状：`textScaler` 只放大文字，容器尺寸全是常量，缩放全靠「刚好放得下」。
项目里已有三处正解，只是没推广：`manual_page.dart:159-181`（圆圈用 `scale(22)`）、
`data_directory_dialog.dart:151`（内容可滚）、`entry_layout.dart:27-33`（断点随字号放宽）。

要做的事：
1. **尺寸随缩放派生**：`height: 48 * scale`、`Icon(size: 20 * scale)`、`SizedBox(width: 96 * scale)`；
   或改用 `minHeight` + `IntrinsicHeight`/`Flexible`，让内容自己撑。
2. **断点乘 scale**：`maxWidth < 480 * textScale`。同一页不要两套口径。
3. **任何「一屏引导页」都必须可滚动**（首启、坏库、扫码、迁移进度），按钮固定在底部。
4. **窄屏不要动用户的字号**（P0-2），只能重排。
5. **与系统字号叠加而不是替换**：`TextScaler.linear(...)` 是替换 —— Android 用户把系统字号调到最大，
   进来反而是固定 125%。这类用户**正是**会去调系统字号的那批人。建议取 `系统值 × 应用档位` 或两者较大值。

### B. 「能点的东西」必须有视觉线索，且带文字

中老年用户不探索（`ui_principles.md` §1.1）。当前违例集中在：
行内操作 `⋮`、纯图标删除、可点但没有箭头的行、只靠 hover 的 tooltip。

改法：`⋮` → 「编辑 / 停用」两个文字按钮（商品页已是范本，`products_page.dart:300-311`）；
可点行 → 行尾 `chevron_right` + 页面顶一句「点一行看它的流水」；
纯图标删除 → 「删除这行」文字按钮。**Tooltip 只用 `triggerMode: tap`**（库存页成本 ⓘ 就是对的，
`stock_page.dart:582-604`），且点击区要够大。

### C. 错误必须出现在「它该出现的地方」，并且说下一步

这是本报告里**最容易一次性拿到最大收益**的一项，因为四个提交页是同一个病：
保存失败 → 只在页顶标红 → 用户以为按钮坏了。

统一模式（建议做成一个可复用的错误定位组件）：

```
保存失败时：
1. 滚到第一个出错字段（复用 keyboard_reveal 的 ensureVisible）
2. 保存按钮上方给一句「还有 2 处要填 —— 已经帮你跳到第 1 处」
3. 每个出错字段就地 errorText（红）；「可以不拦人」的提醒用橙字内联
```

样板已经存在：超收找零（文案在 core `overpay.dart:57-95`，按钮文字随超收变成「记 ¥93 并找零 ¥7」，
`settlement_dialog.dart:316`）。这条线是「内联优先 + 说清下一步」的最佳实践，其余页面照抄即可。

### D. 空态与「无结果」要分开，且都要给出路

三档质量（`ui_principles.md` §1.3 的延伸）：

| 档 | 例子 | 处理 |
|---|---|---|
| 好 | 库存页两段式空态：先问「店里已经有货？」再给「以后新进的货走采购入库」（`stock_page.dart:353-404`） | 保留，推广 |
| 弱 | 单据页 / 三个流水页只有一句「没有…」 | 补「下一步做什么」 |
| 错 | 商品页搜不到时说「还没有商品」（`products_page.dart:199-200`） | 按 `hasQuery` 分两种文案，照 `documents_page.dart:472` |

建议文案模板：
- 搜不到：`没有匹配「XX」的商品。换个词，或点搜索框右边的 × 清空。`
- 真空库：`还没有商品 —— 点上面的「新增商品」，把店里卖的东西录进来。`
- 无流水：`这个商品还没进过货。到「采购入库」开一张单，或回库存页点「重新录入」。`

### E. 一屏一个主数字，字号层级要拉开

中老年用户「看不清」往往不是绝对字号不够，而是**该看的东西不突出**。
- 概览经营卡：金额单独一行 22–24px 加粗，「今日销售 ¥1,280」是这页最想看的东西，
  现在却是 15px 且与标题同量级（`overview_page.dart:274-286`）。
- 库存页主数字（`stock_page.dart:554-561`）已经做对了（`headlineSmall` + 加粗 + 等宽数字），**但缺单位**——
  「5」是 5 件还是 5 箱？建议印成 `5 件`，并把下面那行改成「账面 5 件 · 在途 0 件」。

### F. 正负值必须「三信号」：文字 + 颜色 + 绝对值

做对的：往来方余额「应收 ¥120 / 应付 ¥80」+ 颜色 + 绝对值（`parties_page.dart:376-397`）、
库存页负库存「已超卖，尽快补货」+ 颜色（`stock_page.dart:480-493`）。
做错的：账户余额裸 `¥ -120.00`（`account_page.dart:321-327`）、账户流水无「进账/出账」字样
（`account_flow_page.dart:157-164`）、商品流水数量裸 `-3`（`stock_flow_page.dart:229-235`）。
「现金账户 −120 元」对 60 岁用户是谜语；改成「余额不足 ¥120（欠款）」并上色即可。

### G. 同一个动作只能有一个名字

中老年用户学的是「词 → 位置」的固定映射，同义词会直接打断它。
- 「更改」/「更改位置」/「换一个文件夹」→ 统一「更改」；
- 「司机」/「承运」→ 统一（词汇表已是「司机」）；
- 「恢复」/「恢复启用」→ 统一「恢复」；
- 「账户」/「资金账户」→ 二选一（导航项改动成本更高，建议页面标题随导航）。
- 「余额 / 应收·应付 / 欠款·还款 / 未收·未付」四种说法描述同一件钱的事，建议按场景定两套：
  **往来方视角**用「欠款 / 还款」，**单据视角**用「未收 / 未付」，其余不再新增。

### H. 手机端要「指路」，不要「藏功能」

手机缺页面有裁定依据，但**缺的不是功能，是指路**：
- 概览的指路文案还说「管商品也在底部」（`shell_kind.dart:24-25`），而底部没有商品；
- 手册三章把用户指去手机上没有的「单据」页；
- 反例（做对了的）：`delivery_page.dart:772-779`「请到电脑上收这笔款（这台手机上目前只能开单）」。

建议：在「我的」放一页**「手机上能做什么 / 要电脑上做什么」两列清单**；
所有「手机上做不了」的入口复用 `mobile_guidance_dialog` 的三段式
（为什么不行 → 去哪做 → 做完怎么同步，`mobile_guidance.dart:34-55`），这个结构很好，应推广。

### I. 不可逆的动作要确认，能撤销的优先用撤销

`ui_principles.md` §1.2/§1.3 的判据是「不可逆才弹窗，其余内联 + 撤销」。
现存的偏差不是弹窗太多，而是**该有的地方没有**：
- 签收（`document_detail_page.dart:625-633`）—— 不可逆、无确认；
- 账户停用（`account_page.dart:198-205`）—— 不可逆、无确认、无撤销，哪怕有钱；
- 退货页退款金额超限（`return_service.dart:274-281` 会静默钳成「找零」）—— 无提示。

反之，**不要**为了「统一」给已经做对的三处再加弹窗：退货确认（`return_page.dart:271-290`）、
期初录入确认（`opening_stock_page.dart:204-222`）、停用有余额的往来方（`parties_page.dart:279-303`）。

### J. 少一类控件，就少一类教学成本

同一件事在四页有四种实现，用户就要学四遍（见 §2.2）。建议把三件东西收敛成共用组件：
1. **「两框一行 / 窄屏堆叠」摆法** —— 现在只有明细行做了堆叠（`entry_fields_row.dart:61-70`），
   「账户 + 金额」这一行四页全是写死并排（`sale_page.dart:1541-1601`、`purchase_page.dart:1146-1210`、
   `return_page.dart:426-457`、`:503-551`）。
2. **主数据「停用 / 恢复」** —— 一个控件 + 一套安全等级（建议：余额非 0 或有关联单据时确认，否则撤销 SnackBar）。
3. **列表页骨架** —— 「常驻搜索（带 × 清空） + 结果计数（真实总数） + 清空筛选 + 行箭头」，五页共用。

## 五、做得好、不要动的地方

> 这一节不是客套 —— 改动时最容易顺手把这几处「优化掉」，而它们正是本项目对目标用户最值钱的部分。

1. **字体栈**（`app.dart:1467-1468` + `typography.dart`）：Windows 显式英文族名、Android 不干预，
   连「族名写错会静默降级」都写进注释。这是「判断在纯 Dart、Flutter 只摆放」的最佳样板。
2. **左侧常驻导航 + 三重高亮**（`navigation.dart:97-176`、`app_shell.dart:656-693`）：
   11 个入口全部带文字标签，分组顺序正确，`initial()` 找不到 id 时退回概览而不是空白。
3. **首启对话框**（`data_directory_dialog.dart:126-279`）：三档校验内联、warn 不拦人、
   按钮文案随状态变、内容可滚 —— §1.3 落得最完整的一处。
4. **条码重复：内联橙字、不弹窗、不拦人、文案来自 core**（`product_form_dialog.dart:196-211`、`:503-511`）。
5. **超收找零这条线**（`overpay.dart` → `sale_page.dart:1046-1052` → 按钮文字 → SnackBar）：
   同一份文案单一出处，按钮文字 = 用户动作的最终确认。
6. **库存页的成本三态**（未进货 / 待校准 / 金额，`stock_page.dart:606-641`）：
   把「¥0.00 会让用户以为软件坏了」写进注释并真的改了。
7. **往来方余额三重表达 + 停用但有余额仍显示**（`parties_page.dart:376-397`、`:441-456`）：防「幽灵账」。
