## 零、怎么用（**三层覆盖法**）

每一个功能点，**必须按三档走**，只做第一档等于没测：

| 档             | 问什么                               | 为什么必须                                 |
| ------------- | --------------------------------- | ------------------------------------- |
| **① 正例**      | 正常填、正常保存                          | 只验证「happy path」—— 最容易被自动化测试覆盖的一档      |
| **② 边界 / 反例** | 空值、超限、重复、成对字段只填一半、跨单据冲突           | **这一档才抓得住真 bug**（本项目绝大多数缺陷出在这里）       |
| **③ 持久化**     | **关掉软件、重新打开**，值还在不在；**重启后账目是否一致** | 纯内存正确 ≠ 落库正确；WAL / 迁移 / 标记文件的坑只在重启后暴露 |

**判据只写「看到什么」**（不看日志、不看代码）：

| ❌ 不算判据     | ✅ 算判据                                |
| ---------- | ------------------------------------ |
| 「点了保存，没报错」 | 「**单据详情里主行写着 `牛奶 × 36`，金额 ¥748.00**」 |
| 「导出了文件」    | 「**Excel 打开中文正常、金额列能直接求和**」          |

> 出问题时**先别改任何东西**：截图 + 记下「当时填了什么」→ 按第十二节回报。

## 四、单据与规则（手册 5 / 6 / 7 / 8 / 13 / 14 · RULE-001~005 / 007 / 008）

| #    | 场景                     | 判据（② 档是重点）                                                                                                    |

| 4.1  | **采购入库（RULE-001）**     | ① 采购 10 件、单价 X ⇒ 库存 +10；② 付款**少于**应付 ⇒ 被拦并提示未付金额；③ 重启后应付余额正确                                                  |

| 4.9  | **核销（RULE-004 / 005）** | ① 部分核销 ⇒ 余额递减；② **核销额 > 被核销单未结额** ⇒ 被拒（不能凭空多收）                                                                |

## 九、异常与破坏性（**这一节只能在真机上做**）

| #   | 场景           | 判据                                                 |

## 十、覆盖矩阵（**「不重不漏」的保证方式**）

**三个维度两两交叉，每个格子至少一条用例**：

| 维度          | 取值                                                        | 数量     |
| ----------- | --------------------------------------------------------- | ------ |
| **A. 桌面入口** | 概览 / 销售开单 / 送货 / 采购入库 / 商品 / 库存 / 单据 / 往来方 / 账户 / 设置 / 帮助 | **11** |
| **B. 规则**   | RULE-001~009                                              | **9**  |
| **C. 手工章节** | `manual_content.dart` 的 20 章                              | **20** |
| **D. 覆盖档**  | 正例 / 边界·反例 / 持久化                                          | **3**  |

**清点口诀（交付前照这句过一遍）**：

1. **11 个入口** —— 每个都点开、每个都至少有 1 条用例（第 二~八节覆盖：11/11）；
2. **9 条规则** —— 每条都有正例 **和** 反例（第 4 节：RULE-001~005/007/008 有专条；RULE-006 见 5.1、RULE-009 见 5.3）；
3. **20 章手册** —— 逐章对一遍「这一章讲的功能，我在哪条用例里验过」；**对不上的章就是漏洞**；
4. **3 档** —— 每条用例都问「边界测了吗 / 重启后看了吗」；
5. **横切 5 项** —— 缩放 / 导出 / 备份 / 同步 / 日志（第 六~八节）在每个相关页面各抽查一次。
