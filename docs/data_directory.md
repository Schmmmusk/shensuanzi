# 数据目录策略

> 用户可见的一句话：**你的经营数据放在你自己选的文件夹里，不在任何服务器上。**
>
> 但「用户自己选」如果做得太裸，会引入另一批问题（选到 U 盘、选进 OneDrive、
> 重启后忘了路径）。本文件定义**默认值 + 允许覆盖 + 立刻校验**这条完整链路。

## 一、为什么不能简单地放进 `%LOCALAPPDATA%`

经营数据与缓存**在文件系统里长得一模一样**。

- 清理类软件（包括同作者的 Nova）扫 `%LOCALAPPDATA%` 是常规操作
- `%APPDATA%` 会被漫游同步
- OneDrive 同步 `文档` 目录，而 **SQLite 在同步盘上运行有真实的损坏风险**
  （同步进程会在背后重写文件，而 SQLite 假设只有自己在动这个文件）

结论：数据目录**必须是用户可见、用户可解释的位置**。

## 二、默认位置

首次启动**不弹框**，直接给一个默认值（用户可改）：

```text
D:\神算子数据\                     ← 存在可用的非系统盘时优先
否则 C:\Users\<你>\神算子数据\
```

「可用」= 非系统盘 + 剩余空间充足 + **不是可移动盘 / 网络盘**。

| 选择 | 理由 |
|---|---|
| 优先**非系统盘** | ① 重装系统不丢数据（个体工商户的最大杀手）② 绕开 `%LOCALAPPDATA%` 的清理风险 ③ 备份到 U 盘更顺手 |
| 不默认 `文档\神算子\` | OneDrive 会同步它 —— 见 §一 |
| 不默认 `%LOCALAPPDATA%` | 会被清理软件删 |
| 有固定盘也有 U 盘时选固定盘 | `kind` 明确时固定盘优先；`unknown` 时按盘符顺序 |

> ⚠️ **纯 Dart 拿不到盘类型与剩余空间**（需要 Win32 `GetDriveType` /
> `GetDiskFreeSpaceEx`）。所以：纯 Dart 一律得到 `unknown` / `null`，
> 「是不是 U 盘」这类判断由 **Flutter 侧注入**（`AppEnvironment.drives`）。
> `null` **表示未知，不是表示「没空间」** —— 未知一律放行，不因为拿不到信息就拦人。

### 2.1 ⚠️ 「未知」是从 `detect()` 产生的：**它永不抛异常**

上面那条「未知一律放行」要成立，前提是**「未知」真能走到消费端** ——
而这取决于 `AppEnvironment.detect()` 自己不出事。

`detect()` 是**环境探测**：不是「读机器事实」，是「**尽力**从机器读取事实」。
每个字段都可能取不到，取不到就**降级**为 `null` / `unknown` / 空列表，
**绝不冒泡**。消费端因此必须容忍「全部未知」。

**为什么这是铁律**：`detect()` 在**启动路径**上（`main()` 第一行、
`_ShensuanziAppState` 的字段初始化）—— 抛一次就是「软件打不开」，
而用户只会说这四个字。真机上的机器**不可预测**：离线映射盘、
权限受限目录、网络共享超时、杀毒软件拦截……

| 情形 | 曾经的后果 | 现在的处置 |
|---|---|---|
| **映射了但已离线的网络盘** | `Directory('Y:\\').existsSync()` **抛** `FileSystemException`（`errno 53 找不到网络路径`），**不是返回 `false`** ⇒ 启动崩溃；补了容错之后仍要等 SMB 超时（实测 **63,127 ms**）⇒ 启动白屏 | **换对 API**：枚举改走 `GetLogicalDrives` + `GetDriveTypeW`（只读**本地挂载表**）⇒ 该盘作为 `DRIVE_REMOTE` **正常枚举出来**，整轮实测 **3 ms** |
| 盘符枚举整体失败 | — | 降级为「最低限度环境」（盘列表为空）⇒ 回退到用户目录 |
| 盘符占着位、但类型问不出来（`DRIVE_UNKNOWN` / `DRIVE_NO_ROOT_DIR`） | — | **不进**盘列表，只记进 `probeFailures`（诊断，启动时记一条日志） |
| 环境变量读不到 | — | 同上，降级为「最低限度环境」 |

> ⚠️ **两条独立规则，别合并**：**枚举回答「本机有什么」（事实），候选回答「哪块盘适合放数据」（策略）**。
>
> | 盘 | 进盘列表吗（事实） | 进默认位置候选吗（策略） |
> |---|---|---|
> | 固定盘 / U 盘 | ✅ | 固定盘 ✅ / U 盘 ❌（拔盘就没了） |
> | **远程盘（`DRIVE_REMOTE`）** | ✅ **事实可见** | ❌ 由 `isGoodForData` 排除 |
> | 光驱 / 内存盘 / 类型未知 | ❌ **根本不进** | — |
>
> **为什么光驱 / 内存盘不进列表**：`DriveKind` 只有四档，硬塞成 `unknown` 会被
> 候选放行（`unknown` 是放行的）—— 而**内存盘重启即丢数据**，正是要避免的。
> 所以「未知一律放行」在**枚举层**不适用，见 §2.2。

> **实证**（2026-10-01）：开发机上有一块离线的 `Y:` 映射盘 ——
> `flutter analyze` 0 issues、三个纯 Dart 包 `dart test` 全绿，
> 但 `flutter test` 的 9 个启动场景**全红**，全是这一条。
> 完整记录与裁决见 `docs/reply_review.md` §AT。

### 2.2 ⚠️ 「未知一律放行」的**边界**：用户选择 ≠ 系统推荐

§二 那条「未知一律放行」**不是无条件的** —— 它管的是**用户主动选择的路径**，
不管**系统自动推荐的位置**：

| 场景 | 未知该不该放行 | 为什么 |
|---|---|---|
| 用户手动选了 `Y:\数据`（走 `DataDirectoryPolicy.inspect`） | **放行** | 用户知情、自己承担后果 —— 这就是 §三 warn 的精神（警告不拦人） |
| 系统自动推荐默认数据目录（走 `candidateDataDrives`） | **不参与候选** | 用户可能**不知情**；自动推荐的位置必须是可靠的 —— 用户没有机会为这个选择承担后果 |

**同一条边界还有第二个落点：远程盘（`DRIVE_REMOTE`）。**

| | 结论 |
|---|---|
| **枚举时** | **可见**（事实 —— 本机确实挂着这个盘符） |
| **默认位置候选时** | **排除**（策略 —— 断网 / 对方关机时打不开） |
| **用户手动选它时** | **放行 + 警告**（走 `inspect` 的 `network` 分支，§3.2） |

它与「探测失败的盘（类型问不出来）」是**两条独立规则**，但**结论相同**：
**自动推荐必须是可靠的。**

> ⚠️ **为什么必须写在这里**：否则将来有人看到「枚举返回了 `Y:`、但默认位置没选它」
> 会困惑，或者在别处**再加一遍**远程盘判断 —— 那就是重复（`isGoodForData` 已经在管）。
> 代码侧由 `environment_test.dart` 钉住（映射组 + 「远程盘不进候选」）；
> **文档侧就是本节**。

这正是 §2.1 那条「失败的盘**不进入** `drives`」的产品理由：
若改成「加入但 `kind: unknown`」，`candidateDataDrives` 会把它当成可用的非系统盘
（`unknown` 是放行的）⇒ **默认数据目录可能落到一个连不上的网络盘上**。

> ⚠️ **这两条规则不能被合并。** 若有人把「unknown 都放行」写进
> `candidateDataDrives` 的过滤条件，就是**回归**。
> **代码侧**由 `packages/shensuanzi_app/test/environment_test.dart` 的验收 ①b 钉住；
> **文档侧就是本节** —— 测试守住代码，文档守住意图，缺一不可。

**⚠️ 别和下面这条混淆**：用户手动选了**探测失败**的路径时，走的是
[`inspect(path)`](#三校验规则) 这条**独立的路径校验**，它**不依赖 `drives`** ——
建目录 / 读标记会失败 → 报「这个位置用不了」。
两者一个在「**推荐**」阶段（自动）、一个在「**用户选择**」阶段（手动），
**报告方式也该不同**，不要合并处理。

## 三、校验规则

用户改动位置时**立刻**校验，结论三档：

### 3.1 拒绝（`DirectoryVerdict.reject`）

| 情况 | 提示 |
|---|---|
| 路径为空 / 相对路径 | 请点「更改位置」，从「此电脑」里选一个文件夹 |
| 系统盘根目录（`C:\`） | 不能直接放在 C 盘根目录 |
| `C:\Windows`（含子路径） | 这是系统目录，不能放经营数据 |
| `C:\Program Files` / `(x86)`（含子路径） | 同上 |
| 目录非空**且没有我们的标记文件** | 这个文件夹里已经有别的东西（见 §五） |

### 3.2 警告（`DirectoryVerdict.warn`）—— **能用，但有代价**

| 情况 | 提示 |
|---|---|
| 在 `%LOCALAPPDATA%` / `%APPDATA%` / `%TEMP%` 下 | 清理软件可能把它当缓存删掉 |
| 在 OneDrive / 坚果云 / Dropbox / 百度网盘 等同步目录下 | 同步过程中数据库有可能损坏 |
| 在可移动盘上 | 拔掉之后就打不开了 |
| 在网络盘上 | 断网或对方关机时打不开 |
| 剩余空间不足 200 MB | 报出具体剩余量 |
| 在（非系统）盘根目录 | 不好认，也不好迁移 |

> ⚠️ **警告不拦人。** 中老年用户被拦住会认为「软件坏了」。
> 这里给的是**代价说明 + 怎么办**，由用户自己决定。

### 3.3 放行（`DirectoryVerdict.ok`）

其余情况一律放行，包括用户自己起名字的目录（`D:\我的账本`）。

### 3.4 大小写与末尾分隔符

Windows 路径**大小写不敏感**，`d:\数据` 与 `D:\数据` 是同一个地方。
所有比较走同一套归一化：小写 + 去掉末尾分隔符（盘根除外）。

> 这条不是洁癖：不归一化就会出现「看起来不同、实际同一个」的**绕过**
> —— 例如把 `C:\Windows` 写成 `c:\WINDOWS\` 就绕过了系统目录检查。

## 四、配置文件

| 项 | 值 |
|---|---|
| 位置 | `%APPDATA%\神算子\config.json`（`%APPDATA%` 拿不到时退到 `<home>\.shensuanzi\神算子\config.json`） |
| 内容 | `data_directory` / `ui_scale` / `shop_name` |

**配置不是数据。** 它只记「上次选的路径」「界面缩放」这类**设备偏好**：

- 被清理软件删掉 → 只丢偏好，**经营数据一行都不会少**
- 缩放存这里而不是数据库 —— 它是设备偏好，不是业务数据

**读永不抛。** 配置是外部输入（用户手改、旧版本写的、被写坏过），
任何字段不认识 / 类型不对 → **退回默认值**，不让一个坏字段导致软件打不开。

## 五、标记文件

数据目录里放一个标记文件：

| 项 | 值 |
|---|---|
| 文件名 | `.shensuanzi-data` |
| 内容 | `app` / `schema_version` / `created_at` |

它解决的是「**配置被删之后还能找回数据**」：

> 只依赖配置的话，配置一丢，软件就**不知道**数据在哪 —— 用户会以为数据丢了。

有了标记，「这个目录是神算子的数据目录」这件事**写在数据自己身边**，
用户重选原目录时读到标记就知道是老数据，直接复用。**不需要用户记住路径。**

同时它也是**防误选**的依据：目录非空但没有标记 → 判为 `foreign`，
默认**拒绝**（避免把数据库丢进用户放了别的东西的文件夹）；
用户在 UI 上确认过（「我就要用这个文件夹」）才放行。

## 六、启动恢复逻辑

启动场景**收在一次判定里**（`AppBootstrap.startupDecision()`，场景枚举在
`packages/shensuanzi_app/lib/src/startup.dart`）。UI 只做 `switch`，**不再自己排队** ——
顺序稍错就会互相盖住：**真机踩过**「库损坏被当成首次启动」，选目录向导把
`config.json` 覆盖成默认路径，用户原来的目录再也切不回去。

```text
启动 → 读 config.json
  ├─ 能读出位置
  │    ├─ 位置可用（目录 + 标记都在）且 库能打开 ──→ openExisting（直接进主界面）
  │    ├─ 位置可用但 **库打不开**（坏 / 被占用 / 版本过新）
  │    │                                        ──→ brokenDatabase（错误页）
  │    │       └ 给「重试」（库修好即原样回来）+「换一个文件夹」
  │    │         ⚠️ 绝不走向导：向导会覆盖 config，原目录就从配置里消失
  │    └─ 位置**用不了**（目录没了 / 标记没了 / 路径非法）
  │                                             ──→ recoverLocation（向导）
  │           └ 但**不说「第一次启动」**：说清「上次用的是哪个、该怎么办」
  ├─ 读不出位置（文件在，但 JSON 坏 / 字段丢了）
  │    ├─ 能从原文**抢救**出位置、且库能开 ──────→ salvageConfig（直接进主界面，用户无感）
  │    └─ 抢救不到 ────────────────────────────→ recoverLocation（向导，同上）
  └─ 文件**不存在**（真·第一次启动）
       ├─ 默认位置**已有数据**（有标记） ───────→ firstRunWithData（**先问一句**）
       │      └「继续使用已有数据」/「选一个新位置」，见 §9.3
       └─ 默认位置没有数据 ────────────────────→ welcome（正常首启）
```

**注意**：一条路径「配置里有」并不等于「能用」—— 仍需重新校验。
用户可能把数据目录搬到别处、或把 `D:\` 改成了 `C:\`，
所以判定每次启动都**重跑一遍**（`resolved()` / `unusableConfigured()` 亦然）。

**「库能不能打开」怎么判**：`Db.probe()` —— 只读 `sqlite_master` 的**可打开性探测**，
**没有迁移副作用**（判定阶段绝不能就把库动了）。

**测试怎么确定性覆盖首启分支**：`ShensuanziApp(defaultDataDirectory: …)` 注入
**一个值**，替换掉「机器给的默认位置」（§BR·补 2 裁定 方案 B）——
测试造两个临时目录（一个空、一个带标记）即可分别走到 `welcome` / `firstRunWithData`。
⚠️ 它**不是「假机器」**：注入的路径照样要拿去做**真实的**文件系统判定
（`isShensuanziDir` → `existsSync`）；`AppEnvironment` **仍然不许注入**。
判据一句话：**注入一个值是参数化，注入一个环境是假机器**。

## 七、迁移

设置页提供「更改位置」。校验两条硬约束（都是会造成**数据套娃**的）：

1. 目标本身必须合法（走 §三）
2. 新旧位置**不能互相嵌套** —— 否则搬完形成 `新\旧\数据` 或 `旧\新\数据`，
   用户之后每改一次路径就多套一层

真正的搬迁（**数据 + 备份一起搬**，不是只改配置）由 UI 执行。

## 八、备份位置

备份目录是数据目录的**兄弟目录**，不是子目录：

```text
D:\神算子数据\        ← 数据库
D:\神算子备份\        ← 每日备份
```

**为什么不放子目录**：用户想「把数据拷到 U 盘」时，
如果备份在数据里面，会形成「备份里包含备份」的递归。

**为什么不放 `文档\神算子备份\`**：OneDrive 同步 `文档`。见 §一。

这个设计顺带让备份逻辑**只依赖数据目录的父目录**，
与 `%LOCALAPPDATA%` 完全解耦。

### 8.1 ⚠️ 同一父目录下**不要放两份账套**（备份会共用）

备份目录名是**固定的**「神算子备份」（由父目录 + 常量算出，**不带账套区分**，
见 `DataDirectoryPolicy.backupDirectoryFor`）。因此：

```text
D:\神算子数据\      ┐
D:\神算子备份\      ┘  ← 同一父目录（D:\）下的任意账套都算到这里
D:\分店B数据\       ┐
D:\神算子备份\      ┘  ← 与上面**是同一个文件夹**
```

后果：两本账的自动备份混在一个目录里 —— 30 天保留策略会按时间删掉
「另一本账的备份」，同一分钟的手动包还会因为**同名**被跳过。

**当前处置（2026-10-07 裁定，审计 #2）**：**不改命名**（改名字会动既有用户的
备份目录），而是：

1. 换位置时**备份一起搬**（迁移执行器本来就搬 —— 见 §七），所以「分店 B
   放在 `D:\分店B数据`」这种用法在迁移之后**各有各的备份目录**，自然分开
2. 本节明确写出这条限制：**同一个父目录下只放一份账套**；要多店，
   就放到不同的父目录（如 `D:\店A\神算子数据` + `D:\店B\神算子数据`）
3. 把备份目录名加上账套标识**留到下个大版本**（`Agents.md` 纪律 15 同源：
   面向用户可见的路径变更不能在一个发布周期里硬切）

## 九、对话框与服务入口

### 9.1 服务入口（UI 面对的唯一入口）

`DataDirectoryService` 的四个方法名直接取自 `docs/reply.md` §四 的能力清单：

| 意图名 | 转发到 | 说明 |
|---|---|---|
| `resolveDefault()` | `DataDirectoryPolicy.defaultDataDirectory` | 默认位置。首次启动**不弹框**，直接填进对话框让用户确认或更改 |
| `validate(path)` | `DataDirectoryPolicy.inspect` | 三档校验（§三） |
| `ensureInitialized(path)` | `AppBootstrap.prepare` | 建目录 + 写标记 + 记配置；`createdNow` 区分新建 / 复用 |
| `isShensuanziDir(path)` | `DataMarker.existsIn` | 只看标记文件，回答「我以前的数据还在吗」 |

另有 `startupDecision()`（**启动路径的唯一入口**，§六：一次判定出六个场景）、
`spaceHint()`（容量提示）、`open()`（开库）。

> `existing()` / `unusableExisting()` / `salvagedExisting()` 仍在（各自回答
> 「能不能用」「是不是只有库打不开」「抢救出什么」）—— `startupDecision()`
> **复用**它们，而不是另写一遍判断（两处并行早晚漂移）。

> ⚠️ **本类不含逻辑**，只做「改名 + 转发」。逻辑只有一份，在
> `DataDirectoryPolicy`（纯判断）与 `AppBootstrap`（会落盘）里。
> 在这里复制一份判断 = 两处并行 = 早晚漂移。

### 9.2 对话框状态机

`DataDirectoryDialogModel` 是**纯 Dart** 的状态机，Flutter 侧只负责画。

```text
open()                 → 用默认位置起步（路径 / 结论 / 容量提示）
choosePath(p)          → 用户点了「更改」并选了文件夹 → 重新校验
                          ├─ reject → 不能开始，提示含「怎么办」
                          ├─ warn   → **仍能开始**（警告不拦人）
                          └─ 目录非空且无标记 → 需要二次确认
confirm()              → created / reused / needsForeignConfirm / blocked
confirm(acceptForeign: true) → 「就用这个文件夹」，真正初始化
```

| 设计点 | 理由 |
|---|---|
| `confirm()` **不抛异常**，只返回结论 | 失败也要有结论，UI 才知道该显示什么 |
| 改路径**作废上一次结果** | 否则会拿旧的成功结果去开库，而那个目录已经不是用户选的了 |
| 二次确认**不是拒绝** | 用户可能就是要放在这个文件夹里。默认拒绝只是防误选 |
| 提示同时给**图标 + 颜色 + 文字** | 色觉异常的比例不低，不能只靠红绿区分 |
| 按「开始使用」期间禁用按钮 | 防重复点 |

### 9.3 第 1 天只做这一个对话框

`docs/reply.md` §一 把向导 5 步拆开看，**只有第 2 步（数据位置）是硬依赖** ——
没有它，数据库不知道放哪，程序根本起不来。其余 4 步（欢迎 / 店名 / 账户 / 完成）
全部**可后补**，而且它们的设计依赖核心功能的行为（开单页真做出来才知道
店名与账户该怎么用），所以留到第 10 天回补。

**首启流程**（全貌见 §六 的场景表；这里只展开「真·第一次启动」那一支）：

```text
启动 → startupDecision()
  ├─ 配置文件不存在 = 真·第一次启动
  │    ├─ 默认位置**已有数据**（重装软件 / 解压到别处 / 双击第二份 exe）
  │    │     → **先问一句**：「这个位置已经有神算子的数据」
  │    │        ├─ 继续使用已有数据 → 复用那份数据（**一个字节都不动**）
  │    │        └─ 选一个新位置     → 「选择数据存放位置」对话框
  │    └─ 默认位置没有数据 → 「选择数据存放位置」对话框（带欢迎语）
  └─ 其它场景（库坏 / 配置损坏 / 位置失效）见 §六 —— **一概不说「第一次启动」**
```

> ⚠️ **「默认位置已有数据要先问」是必须的**（§审查 OBS-11 前半）：默认位置在同一台
> 机器上每次都是同一个，而「重装软件 / 解压到别处 / 双击第二份 exe」都会走到这里 ——
> 不问的话，用户直接点「开始使用」就挂到同一份数据上了（他还以为「换了个文件夹就是新数据」）。
> 它与 OBS-14（单实例锁）是**姊妹问题**：一个是**引导**到同一份数据，一个是**并发**打开它。

主界面是**空骨架**：把「数据在哪」说清楚 + 列出核心闭环五个入口（标「待实现」）。
按 `docs/ui_principles.md` §1.1，入口必须**常驻可见 + 带文字**。

### 9.4 纯 Dart 那一半 vs Flutter 那一半

| 层 | 位置 | 怎么验证 |
|---|---|---|
| 路径策略 / 校验 / 标记 / 恢复 / 对话框状态机 | `packages/shensuanzi_app`（纯 Dart） | **`dart test` + 自检**，全自动 |
| 对话框 widget / 启动流程 / 主界面 | 根 `lib/src/`（Flutter） | 只能 `flutter analyze` + `flutter test` |

这个切分的目的是**把出错面压到最小**：Flutter 那一层只做「摆放控件、
调选择器、把 model 的结果 pop 回去」，没有判断逻辑。

**尚缺（不阻断第 1 天）**：

- **真实盘类型与剩余空间**：纯 Dart 拿不到（需 Win32 `GetDriveSpace`），
  所以对话框的容量提示目前可能为空 —— 界面已对 `null` 处理（不显示那一行）
- **界面缩放**：`UiScale` 档位已在配置里，但接入 `textScaler` 属第 11 天的设置页

## 十、实现映射

| 关注点 | 位置 |
|---|---|
| 默认位置 / 校验 / 备份路径 / 迁移校验 | `packages/shensuanzi_app/lib/src/data_directory.dart` |
| 本机事实（盘符、环境变量） | `packages/shensuanzi_app/lib/src/environment.dart` |
| 配置读写 | `packages/shensuanzi_app/lib/src/app_config.dart` |
| 标记文件 | `packages/shensuanzi_app/lib/src/data_marker.dart` |
| 启动恢复 / 打开数据库 | `packages/shensuanzi_app/lib/src/bootstrap.dart` |
| **服务入口**（UI 面向，§9.1 的四个意图名） | `packages/shensuanzi_app/lib/src/data_directory_service.dart` |
| **对话框状态机**（纯 Dart，§9.2） | `packages/shensuanzi_app/lib/src/dialog_model.dart` |
| 对话框 widget / 启动流程 / 空主界面 | 根 `lib/src/ui/`、`lib/src/app.dart`（Flutter，只做摆放） |
| 系统「选择文件夹」 | 根 `lib/src/folder_picker.dart` —— **全项目唯一调用 Flutter 插件的地方，也是唯一被注入的依赖**（`ShensuanziApp(pickDirectory:)`） |

**为什么单独一个包**：数据目录策略既不是业务规则（core）也不是主机服务（host），
它是**运行环境**。放进去会污染那两个包的语义。

**为什么全部可测**：真机取值只在 `AppEnvironment.detect()` 做一次，
判断逻辑全是纯函数 —— 测试可以构造「有 U 盘 / 有网盘 / 无 D 盘」的机器，
**不需要真的插一个 U 盘**。

Flutter 侧需要额外注入的（纯 Dart 拿不到）：

- 每块盘的**真实类型**（`GetDriveType`）与**剩余空间**（`GetDiskFreeSpaceEx`）
- 目录选择对话框（`file_selector` / `FilePicker`）

## 十一、与威胁模型的衔接

本策略缓解的威胁（见 [`threat_model.md`](threat_model.md) §2.1）：

| 威胁 | 缓解 |
|---|---|
| 数据文件被清理软件误删 | 默认落在非系统盘、不在 `%LOCALAPPDATA%`；选中受限位置时警告 |
| 数据库被同步盘写坏 | 识别网盘目录并警告 |
| 用户找不到自己的数据 | 默认路径可解释、标记文件可恢复、README 与向导双重说明 |
| 误把数据库丢进别人的文件夹 | 非空且无标记 → 默认拒绝 |
