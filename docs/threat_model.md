## 一、信任边界

**信任**：家庭 / 店铺局域网（WiFi 或以太网）。

**不信任**：公网、未知 WiFi、物理接触主机的陌生人。

## 二、防御范围

### 2.1 防

| 威胁 | 缓解 |
|---|---|
| 未授权设备连接 | Token 鉴权 + 已配对设备列表可踢出（`/api/health` 无鉴权但只回版本与时间） |
| **端口被公网可达** | ⚠️ **部分防**：服务**监听本机全部网卡**（`InternetAddress.anyIPv4`，`http_server.dart:116`），只把**局域网地址**公布给手机（二维码 / 配对载荷用的是 `local_ip` 探测出来的那个地址）。真正的护栏是 Token + 局域网拓扑；**若路由器把 17890–17900 映射出去，端口就是可达的**。收紧成「真的只绑局域网网卡」见 §七 **TM-1（登记为下次解决，本次只改文案）** |
| SQL 注入 | 表名 / 列名白名单 + 参数化查询 |
| 同步重复提交 | 幂等键 = 实体 `id` |
| 时钟偏差污染 | `seq_no` 主导排序，`occurred_at` 仅展示 |
| 备份文件被误删 | 备份放在数据目录的兄弟目录 + 自动备份 + 超过 3 天红字提醒（**防的是误删，不是防拷走**） |

⚠️ **「备份文件被拷走」不在防御范围**（原稿列在 §2.1，2026-11-09 移到 §2.2）：
备份是**裸 SQLite 明文文件**，v1 **不做加密**（见 §3.5）。

### 2.2 不防

| 威胁 | 理由 |
|---|---|
| **备份文件被拷走 / 主机被拿走** | 备份与主库都是**明文裸 SQLite**，v1 不做加密（§3.5 是**取舍**不是遗漏）。物理接触 = 拿到全店数据 |
| 局域网内恶意设备 | 家庭 / 店铺场景，无此假设 |
| ARP 欺骗 | 同上 |
| 物理访问主机 | 用户自己负责 |
| Token 泄露（明文进二维码） | v1 无 TLS 的取舍。见下文 |
| 中间人攻击 | 同上 |
| 微信 / 支付宝 API 劫持 | v1 不接入 |

## 三、已知取舍

### 3.1 无 TLS

**决策**：v1 不引入 TLS。

**理由**：自签证书对个体工商户门槛太高，会直接劝退。用户不会为了装一个记账软件去搞证书。

**缓解**：

- Token 为 32 字节随机数，暴力破解不可行
- 设置页可一键重置 token，所有设备重新配对
- README 明确写："设计假设：局域网可信"

### 3.2 明文 token 进二维码

**决策**：二维码含 token 明文。

**理由**：配对必须一次性完成，用户不会手动输密码。

**缓解**：

- 二维码只在配对时显示，配完即隐藏
- Token 可重置
- 物理接触二维码 = 物理接触主机，已在"不防"范围

### 3.3 无 mDNS（v1）

**决策**：v1 只做二维码配对。

**理由**：Windows 防火墙入站规则是独立战场，会拖慢 MVP。

**代价**：IP 变化后需重新扫码。

**v1.5 计划**：引入 mDNS 自动发现，同时处理防火墙引导。

### 3.4 允许负库存

**决策**：允许。

**理由**：离线优先下**必然**出现本地超卖。事后拒绝无法自洽。

**缓解**：

- UI 红色告警
- 提供"补货建议"入口
- 负库存出库成本按最近一次入库价计算

### 3.5 不加密数据库与备份

**决策**：**v1 不做加密**。主库与备份都是**明文裸 SQLite 文件**。

**理由**：加了口令就多一条「**忘记密码 = 数据全丢**」的路径，而目标用户记不住密码。
一份打不开的账，比一份被拷走的账更常见、也更致命。

**代价（必须说清）**：拿到那台电脑或那个备份文件夹的人，就拿到了全店数据 ——
所以「备份文件被拷走」列在 §2.2 **不防**。

**"默认不加密"是承诺，不是妥协**：数据开放，任何时候都能用任何 SQLite 工具打开，
不怕被软件锁死。**将来若要加**，必须先设计好密钥丢失的恢复路径，否则不做。

## 四、数据安全

### 4.1 备份

- 每天自动备份到**数据目录的兄弟目录**（默认 `D:\神算子备份\`），
  格式是**裸 SQLite 文件**（不是 ZIP —— 见 `Agents.md` §4.5「数据可携带性原则」）
- 文件名带 **schema 版本 + 日期时分**；手动包加 `m-` 前缀
- 保留：**30 天内全留**；30 天前的**自动包**删除，但**每个自然周最早的一份豁免**
  （连续 30 天都错录也还剩每周一个还原点）；**手动包永不自动清理**
- 空库（没有任何单据）**不自动备份**，也不提醒
- 备份目录可在资源管理器直接打开；**没有单独的「导到 U 盘」按钮** ——
  把文件夹拷走就行（少一个按钮 = 少一处「以为点过就备好了」的误会）

> ⚠️ **不放 `文档\神算子备份\`** —— OneDrive 会同步 `文档`，
> 而 SQLite 在同步盘上被后台重写有真实的损坏风险。
> 备份位置**只依赖数据目录的父目录**，规则见
> [`data_directory.md`](data_directory.md) §八。

### 4.2 加密

**v1 不做**（取舍见 §3.5）。原稿写的 SQLCipher 加密、Windows Credential Manager
存密钥、备份包 AES-256 **均未实现**，已裁定不做 —— 别照着实现，也别照着承诺。

### 4.3 数据导出

- 提供 CSV 导出：**商品 / 库存 / 往来方 / 单据 / 往来流水**五处（`docs/…export`，金额不带千分位）
- **不单独做「导出原始 SQLite」** —— 备份本身就是裸 `.db` 文件，
  想要原始库直接把最近一份备份拷走即可（少一条功能 = 少一处会漂移的实现）
- 用户数据永远可迁移

### 4.4 数据目录策略

数据**放在哪**本身就是一个威胁面：经营数据与缓存**在文件系统里长得一模一样**，
而清理类软件（包括同作者的 Nova）扫 `%LOCALAPPDATA%` 是常规操作。

**默认位置**（首次启动直接给出，用户可改）：

```text
D:\神算子数据\                     ← 存在可用的非系统盘时优先
否则 C:\Users\<你>\神算子数据\
```

| 风险 | 缓解 |
|---|---|
| 被清理软件误删 | 默认落在**非系统盘**、不在 `%LOCALAPPDATA%`；选中受限位置时**警告** |
| 在同步盘上被写坏 | 识别 OneDrive / 坚果云 / Dropbox 等目录名，**警告** |
| 拔盘后打不开 | 识别可移动盘，**警告** |
| 无写权限导致创建失败 | 拒绝系统目录（`C:\Windows`、`C:\Program Files`）与系统盘根目录 |
| 配置丢了找不到数据 | 数据目录里放标记文件 `.shensuanzi-data`，**重选原目录即可复用** |
| 误把数据库丢进别人的文件夹 | 目录非空且无标记 → **默认拒绝** |

**为什么是「警告」而不是「拒绝」**：中老年用户被拦住会认为「软件坏了」。
警告给的是**代价说明 + 怎么办**，由用户自己决定。

完整规则（默认值、校验三档、配置文件、标记文件、恢复与迁移）见
[`data_directory.md`](data_directory.md)。

## 五、README 中的威胁模型声明

以下文本必须与 `README.md` §威胁模型**逐字一致**（改一边必须改另一边）：

```text
信任边界：家庭 / 店铺局域网
不防御：局域网内的恶意设备、ARP 欺骗、物理访问主机
不防御：控制了这台电脑的人、拿到备份文件的人 —— 主库与备份都是明文文件（v1 不做加密）
防御：误删（自动备份 + 30 天保留）· 未授权设备连接（Token）· SQL 注入（白名单 + 参数化）
```

> ⚠️ **2026-11-09 更正**：原文写「防御：外部网络访问、数据文件被拷走、备份包泄露」——
> 这三条**都不成立**（服务绑 `0.0.0.0`；不加密）。那是设计意向，不是实现。
> 对用户说「我们防住了拷走」，等于让他放心把装库的笔记本借出去。

## 六、未来增强（不在 v1 范围）

- mDNS 自动发现
- TLS（自签证书或 Let's Encrypt）
- 加密（须先设计密钥丢失的恢复路径，见 §3.5）
- 微信 / 支付宝 API 自动对接
- 云端同步（可选，用户自备服务器）
- 多主机（连锁店场景）
