# 威胁模型

> 明确写出**防什么、不防什么**，避免实现者过度设计或错误假设。

## 一、信任边界

**信任**：家庭 / 店铺局域网（WiFi 或以太网）。

**不信任**：公网、未知 WiFi、物理接触主机的陌生人。

## 二、防御范围

### 2.1 防

| 威胁 | 缓解 |
|---|---|
| 备份文件被拷走 | SQLCipher 加密数据库 + 备份包 AES-256（用户可选） |
| 未授权设备连接 | Token 鉴权 + 已配对设备列表可踢出 |
| 外部网络访问 | HTTP 服务只监听局域网网卡 |
| SQL 注入 | 表名 / 列名白名单 + 参数化查询 |
| 同步重复提交 | 幂等键 = 实体 `id` |
| 时钟偏差污染 | `seq_no` 主导排序，`occurred_at` 仅展示 |

### 2.2 不防

| 威胁 | 理由 |
|---|---|
| 局域网内恶意设备 | 家庭 / 店铺场景，无此假设 |
| ARP 欺骗 | 同上 |
| 物理访问主机 | 用户自己负责 |
| Token 泄露（明文进二维码） | v1 无 TLS 的取舍。见下文 |
| 中间人攻击 | 同上 |
| 微信 / 支付宝 API 劫持 | v1 不接入 |

## 三、已知取舍

### 3.1 无 TLS

**决策**：v1 不引入 TLS。

**理由**：自签证书对个体工商户门槛太高，会直接劝退。用户不会为了装一个记账软件去搞证书。

**缓解**：

- Token 为 32 字节随机数，暴力破解不可行
- 数据库文件本身可加密（SQLCipher）
- 设置页可一键重置 token，所有设备重新配对
- README 明确写："设计假设：局域网可信"

### 3.2 明文 token 进二维码

**决策**：二维码含 token 明文。

**理由**：配对必须一次性完成，用户不会手动输密码。

**缓解**：

- 二维码只在配对时显示，配完即隐藏
- Token 可重置
- 物理接触二维码 = 物理接触主机，已在"不防"范围

### 3.3 无 mDNS（v1）

**决策**：v1 只做二维码配对。

**理由**：Windows 防火墙入站规则是独立战场，会拖慢 MVP。

**代价**：IP 变化后需重新扫码。

**v1.5 计划**：引入 mDNS 自动发现，同时处理防火墙引导。

### 3.4 允许负库存

**决策**：允许。

**理由**：离线优先下**必然**出现本地超卖。事后拒绝无法自洽。

**缓解**：

- UI 红色告警
- 提供"补货建议"入口
- 负库存出库成本按最近一次入库价计算

## 四、数据安全

### 4.1 备份

- 每天自动备份 SQLite 到 `文档/神算子备份/`
- 备份为 ZIP 包
- 保留最近 30 天
- 提供"一键导出到 U 盘"按钮

### 4.2 加密

- **默认不加密**。备份是普通 ZIP，未加密时可直接用任何 SQLite 工具打开
- 用户可选开启 SQLCipher 加密
- 密钥存 Windows Credential Manager（Windows）/ Android Keystore（Android）
- 开启加密后，备份包自动 AES-256

**"默认不加密"是承诺**：数据开放，不怕被锁死。加密是可选增强，不是默认。

### 4.3 数据导出

- 提供"导出为 CSV"功能（商品、单据、流水）
- 提供"导出原始 SQLite"功能
- 用户数据永远可迁移

## 五、README 中的威胁模型声明

以下文本必须写入 `README.md`：

```text
信任边界：家庭 / 店铺局域网
不防御：局域网内的恶意设备、ARP 欺骗、物理访问主机
防御：外部网络访问、数据文件被拷走、备份包泄露
```

## 六、未来增强（不在 v1 范围）

- mDNS 自动发现
- TLS（自签证书或 Let's Encrypt）
- 微信 / 支付宝 API 自动对接
- 云端同步（可选，用户自备服务器）
- 多主机（连锁店场景）
