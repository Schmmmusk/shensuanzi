## 一、A0b 白盒验收（装机后**第一件事**，约 3 分钟）

> 目的：不是看「跑得起来」，是看「跑得干净」—— 有没有在后台刷错误。

```powershell
adb logcat -c                      # 1) 清空缓冲
# 2) 在手机上操作：启动神算子 → 概览 → 开单 → 库存 → 往来 → 我的 → 设置 → 再回概览
adb logcat -d > D:\shensuanzi\shensuanzi\build\logcat-a1.txt      # 3) 抓取
Select-String -Path D:\shensuanzi\shensuanzi\build\logcat-a1.txt `
  -Pattern "SqliteException|Foreign key|AndroidRuntime|FATAL|Camera permission|E/flutter"
```

**判据**：

| 现象 | 结论 |
|---|---|
| 上面这条**无输出**（或只有无关的系统行） | ✅ 通过 |
| 出现 `SqliteException` / `Foreign key` / `FATAL` / `E/flutter` | ❌ **停下，把这几行原文贴回来** |
| 出现一次 `Camera permission` | ⚠️ 扫码页申请相机权限是**正常**的；只有「denied / 反复申请 / 崩溃」才算问题 |

## 二、C3 复收（原反馈 ① ② ③ ④）

> 背景：2026-10-07 真机跑 §BS 验收 ①–⑦ **全过**；同批带出四问题（§CF）。
> 其中 ② 已由 D1/D2b 覆盖；①③④ 的修复已落地，**本次就是复验它们**。

### ① 收款找零行溢出（窄屏）—— 复验

**在哪**：开单（销售）→ 选商品 → 收款区选**现金** → 收款额填一个**大于合计**的数。
**期望**：找零行**不溢出** —— 不出现黄黑斜纹、日志里不出现 `RenderFlex overflowed`；窄屏下「找零」独立成行。
**反向**：把收款额改回**小于**合计 ⇒ 找零行不该显示负数。

### ③ 标题 / 流水行 / 导出按钮（窄屏限幅）—— 复验

**在哪**：**往来 tab → 点某个往来方 → 进入「×× 的流水」页**（这是 C3·③ 的原始现场）。
**期望（三件，都已落地）**：

| 看什么 | 期望 |
|---|---|
| AppBar 标题 | 不再被挤成「平⋯」—— 显示完整「×× 的流水」 |
| 右上按钮 | 是**「导出流水」四字**（原来是「导出该往来方的全部流水」，把标题挤爆） |
| 每行 | **两行**：类型标签 + 金额 / 单号 + 日期 —— 单号不再从中间硬折行 |

**缩放**：在**标准**与**最大**各看一遍（该页窄屏限幅 `maxScaleFactor: 1.15`，宽屏不动）。

### ③-b ⚠️ 「图标不随缩放」—— **本版未实现，本轮无法验证**

裁定要求「图标不随缩放（≤1.2）」，但我核对全仓：**没有任何 `IconThemeData` / `iconTheme` 覆盖**，
全局只挂了 `TextScaler.linear(uiScale)`（`app.dart:1456`）⇒ **图标仍随缩放放大**。
⇒ 你若在最大档看到「图标撑破按钮/圆圈」，那是**已知未做项**，不用当新 bug 报；我另起一件落地。

### ④ IME 键盘遮挡 —— 复验

**在哪**：开单页 / 商品选择器 / 客户选择器 —— 用输入法**打字**（含候选栏弹出与收起）。
**期望**：**正在输入的那个字段始终在键盘上方可见**，不会被候选栏推走。
**做法**：每个输入框都点一遍、打几个字、再切到下一个 —— 重点看**最下面那格**。

### ② 主数据入队（手机建档）—— 复验（原反馈「手机建档是刚需」）

**在哪**：**开单 → 选销售/采购/送货 → 点商品选择器 → 「＋新建商品」**
（`sale_page.dart:1793`；手机端 `canCreateProducts = true` ⇒ 应该直接进表单，而不是弹引导）。
**期望**：

1. **能建**：填名称 + 单位 → 保存成功，**不弹「到电脑上建」的引导**；
2. **立刻可用**：保存后该商品出现在选择器里，能直接开单；
3. **推得出去**：开单 → 保存 → 三态条走「已同步」→ **回电脑上确认商品已在主机**。

## 三、v3 真机验收 5 步（包装换算 + 整单让价）

> ⚠️ **口径提醒**：§BD·十六 的详解版是**桌面口径**（「左侧导航 → 商品 / 单据」）。
> **手机壳没有商品页、没有单据页** ⇒ **第 4 步（开单据看明细行）在手机上做不到**。
> ⇒ **推荐整套在 Windows 桌面版跑**（等价且能拿到第 4 步的证据）；想在手机跑也可以，
> 但**第 1 步换路径**（开单 → 商品选择器 → ＋新建商品）、**第 4 步必须回电脑核对**。

**前置**：别拿老商品测 —— 老商品没填包装两列，**不会**出现切换 chips（那正是第 5 步的反向验证）。

| 步 | 做什么 | 期望（判据） |
|---|---|---|
| **1** | 建档：名称「牛奶」、**单位「个」**、售价随便；再填 **「包装单位」= 箱**、**「1 包 = 多少」= 12**（1 箱 = 12 个）；保存后**再打开编辑** | 两格**回显** `箱` / `12` |
| **2** | 销售开单选它 ⇒ 数量框下出现**两枚 chip「个」「箱」**；点**「箱」** ⇒ 标签变「**数量（箱）**」；数量 **3**、单价 **250.00** | 该行小计 = **¥750.00**（= 3 箱 × 250，**不是** 36×250=9000）；合计同为 750 |
| **3** | 「整单让价（可选）」填 **2.00** | 合计 → **¥748.00**；该行小计 → **¥748.00**；无红色报错 |
| | 边界：让价填 **800**（超过合计） | **橙色**提示「让价不能超过合计 ¥750.00」，合计**不变**；改回 2.00 |
| **4** | 选客户（赊账）或配收款 → 保存 → 去**单据**页点开这张销售单 | 主行 `牛奶 × 36`、金额 **¥748.00**（**×36 是核心**：填 3 箱 ⇒ 库存按 **36 个**扣）；行下小字「**让价 -¥2.00（折前 ¥750.00）**」 |
| | 回**商品/库存**看牛奶库存 | **少了 36**（不是 3） |
| **5** | 反向：选一个**没填包装两列**的老商品开单 | 数量下**不出现** chips，标签就是「数量 *」，行为与升级前**完全一样** |
| | （可选）只填「包装单位」不填数量（或反之）→ 保存 | 报「**就要给包装起个名字**」/「**就要填 1 包 = 多少个**」—— 成对启用防半配置 |
