## 二、4a 执行计划断言（本批的确定性门禁）

| 2 | `inTransitByProduct` | 用 `idx_documents_type_status` | — |

## 四、4c 修复清单（按「用户能感知」排序，先做 3 条）

### 4c-1 开单页每敲一键全表聚合（报告 #1，最高优先）

**现状**：`Service.stockSnapshot()` 每次 `setState` 都跑
`SELECT product_id, SUM(quantity) FROM stock_ledger GROUP BY product_id`
（30 万行）。用户的体感是**打字掉帧**。

**改法（甲，推荐）**：开单页把库存快照**缓存在页面状态里**，只在
「进页 / 保存成功 / 从选择器换商品」时重取 —— 也就是把「每键一次」降为「每单一次」。
**不做**全局缓存（失效点太多，跨页共享的缓存最难保证正确）。

**风险**：页面生命周期内库存可能被别人改（单机无并发；手机端是镜像只读）⇒ 可接受。
**验收**：`perf_monitor` 连打 20 个数字，`grep stock_group` 的调用次数从 ~20 降到 1（加一行 debug 计数即可）。

### 4c-2 库存页 5 次聚合 → 1 次（报告 #3）

**现状**：进页跑 `stockByProduct` + `inTransitByProduct` + `costByProduct` +
`inboundProductIds` + `hasAnyStockLedger`，前三个都是全表聚合。

**改法**：合并成**一条** `SELECT product_id, SUM(quantity), SUM(total_cost) …`
（账面 + 成本一次算完），`inboundProductIds` 用 `EXISTS` 子查询并入同一轮；
`hasAnyStockLedger` 用 `SELECT 1 … LIMIT 1`（本来就是）。
**风险**：SQL 变长，但都在 `QueryDao` 一处；返回结构不变 ⇒ 页面零改动。
**验收**：`perf_bench` 的 `stock_group` + `stock_cost` 两条耗时之和 vs 单条；进页总时长 < 300 ms。

### 4c-3 单据页搜索（报告 #11）

**现状**：四路 `LIKE '%q%'` + 每行 2 个相关子查询 + `SCAN d`。

**改法**：**两段查询** —— 第一段只取「命中的 id + 排序键」（`SELECT d.id … ORDER BY 分桶 DESC LIMIT 200`），
第二段用 `IN (200 个 id)` 取完整行 + 派生列。排序从「2 万行」降到「200 行」。
`LIKE '%q%'` 本身无法走索引（前缀通配），**不引入 FTS**（v1 不值）。
**风险**：两段之间数据变动 ⇒ 第二段按 id 取，缺失的行跳过（与现有「坏行跳过」同款）。
**验收**：`perf_bench` 的 `doc_search` 在 2 万单下 < 150 ms；列表首屏 < 300 ms。

### 4c-4 次要（有数字再决定）

| 报告 # | 现状 | 改法 | 何时做 |

| #12 | 成单保存末尾 `partyBalances()` 全表扫，只为 SnackBar 一句「累计欠款」 | 改成「只算这一方」的 `partyBalanceOf(partyId)` | 若基线显示保存 p95 > 200 ms |

## 六、顺序与风险

**顺序**：4a 断言（先立门禁）→ 4b 基线（拿数字）→ 4c-1 → 4c-3 → 4c-2 → 4c-4（按数字）。

- 4a 是**唯一能进 CI 的**，先做；它红了说明有人改 SQL 改坏了索引。
- 4b 必须在**修之前**跑，否则没有对照。
- 4c 每条都**独立可回滚**（单文件改动 + 行为不变），不做「一次性重写查询层」。

**风险**：
| 风险 | 应对 |
|---|---|
| 缓存库存快照导致「刚保存的单看不到」 | 保存成功回调里显式重取（4c-1 的验收点） |
| 两段查询之间数据变化 | 第二段按 id 取，缺失即跳过；不加事务（读一致性对本场景无意义） |
| 计划断言过紧（SQLite 升级改计划） | 断言只锁「用了哪个索引 / 有没有全表 TEMP B-TREE」，不锁顺序与细节 |

> 4a first (the only CI-able layer), then baseline, then fixes one by one.

## 七、要你裁的两件

| # | 决策点 | 甲（推荐） | 乙 |
|---|---|---|---|
| ① | 开单页库存快照的缓存范围 | **只缓存在页面状态里**（进页/保存/换商品时重取） | 全局缓存 + 失效通知（跨页共享，失效点难保证） |

> Two rulings: page-local snapshot cache (A) and no FTS5 (A).
