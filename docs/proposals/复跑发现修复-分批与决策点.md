## 一、批次 A（P1，两条）

### A-1 · F1 草稿只活一次导航

**现象**：在开单页填了内容 → 切走 → 切回来（没点「恢复草稿」）→ 再切走，**草稿没了**。

**根因**（`lib/src/ui/purchase_page.dart` 的 `_writeDraftNow()`，销售/送货两页同款）：

```dart
if (!purchaseDraftHasContent(draft)) {
  store.delete(DraftKind.purchase);   // ← 把"还没恢复的"草稿一起删了
  return;
}
```

第一次离开：表单有内容 ⇒ 写盘。第二次进页：草稿只被读进 `_restoreRaw` 等用户点「恢复」，
**表单仍是空的**。第二次离开：当前表单空 ⇒ `delete()` ⇒ 上一份被抹掉。

**修法**：`_restoreRaw != null`（存在待恢复草稿）时**一律不许删**。

**测试（先红后改）**：
1. 进页 → 填商品与数量 → `unmount`（草稿写入）→ 断言文件存在；
2. 再 `pump` 同一页（不点恢复）→ `unmount` → **断言文件仍存在**（当前会红）；
3. 点「恢复」→ 再 `unmount` → 文件内容等于恢复后的表单；
4. 点「放弃」→ 文件被删（显式意图才允许删）。

**反向灵敏度**：把守卫改成 `if (false) return;` ⇒ 用例 2 必须红。

**风险**：`_restoreRaw` 只在 `initState` 设置、恢复/放弃时清空。若用户在"有草稿待恢复"的页面上
**主动清空**了表单再离开，守卫会让旧草稿继续存活 —— 这是**有意的**（宁可多留一份，不可默默丢）。

### English

Root cause: `_writeDraftNow()` treats "the form is empty" as "the user cleared the draft", so the
**un-restored** draft is deleted on the second navigation. Fix: never delete while `_restoreRaw != null`.
Test first (must go red), then the guard; reverse-sensitivity by neutering the guard.

### A-2 · F14 换主机后同步永久失败

**现象**：「忘记这台主机」→「扫码连接主机」→ 扫码成功 → 首次同步必报

```
Bad state: 落库 products 的行（…）失败：UNIQUE constraint failed: products.code
```

重试永远失败，界面**没有**任何"重建镜像"的出口。

**根因（两处判定叠加）**：

1. `packages/shensuanzi_app/lib/src/mobile_sync_service.dart:428`：

```dart
lastHostSwitchHeldEntries =
    previous != null && previous.hostId != info.hostId   // ← 关键
    ? resetForNewHost(previousHostId: previous.hostId) : 0;
```

「忘记这台主机」会删掉 `pairing.json` ⇒ 再扫码时 `previous == null` ⇒ **不重建镜像**。

2. 另一条重建路径要求 `hostSchema > mirror.schemaVersion`；旧主机与新主机**同为 schema 5** ⇒ 不触发。

⇒ 镜像里留着旧主机的 `P0001/P0002`，新主机全量拉取插入同 `code` ⇒ UNIQUE 冲突。

**修法（按用户 2026-10-25 裁定："自动归档旧主机及其数据，然后再走现有流程"）**：

1. **镜像自己记 hostId**（`mirror_meta` 表，或 `PRAGMA application_id` + 一张单行表）——
   **不再依赖 `pairing.json` 是否存在**（用户点「忘记」是正常路径，不是异常）；
2. **判定依据 = `host_id`（应用层身份），不是 IP**（用户 `reply.md` 补强：
   「老王家和老李家都是 `192.168.1.1` 网段，只认 IP 会串账」）。三种情形必须分开：

| 情形 | 判定 | 行为 |
|---|---|---|
| **A** 同一台主机换了 IP（换路由器 / DHCP 续租） | `扫到的 host_id == mirror.hostId` | **只更新 `pairing.json` 的 IP/端口**；**不归档、不重建**；积压 `pending` 正常推给新 IP |
| **B** 换了电脑 / 换了一家店（IP 甚至可能相同） | `host_id` 不同 | **归档**：旧镜像 + 队列整体移到 `archive/<旧 hostId>-<yyyyMMdd-HHmm>/` → 清空镜像 + 清游标 → 用新 hostId 重建 → 全量拉取 |
| **C** 全新手机首次扫码 | 镜像里没有历史 `hostId` | 直接建库、写入 hostId、全量拉取，**没有归档这一步** |

3. **归档 ≠ 删除**：设置页给一行「历史主机数据（N 份）」，可查看/删除；
4. 兜底出口：设置 → 多设备同步 → 「重建本机数据副本」（错误文案里已经写了这句，界面却没有）。

**测试（含用户点名的两条防呆）**：
1. **同 IP、异 UUID** ⇒ **必须触发归档**（证明身份判定不依赖 IP）；
2. **同 UUID、异 IP** ⇒ **必须不归档**，且积压 `pending` 能正常补传（证明对 IP 变化平滑）；
3. `pairing.json` 不存在但镜像非空（点过「忘记」）⇒ **必须重建/归档**（当前红，F14 原始现场）；
4. 归档目录里能找到旧镜像与队列（文件存在 + 能只读打开）；
5. 情形 C（空镜像）⇒ 不产生 `archive/` 目录。

**风险**：归档要复制镜像库，手机上可能有几十 MB —— 必须**异步 + 进度**，且失败不能阻断配对
（失败就退回"直接重建"，但要在界面上说清"旧数据没能归档"）。

### English

Two overlapping checks cause the deadlock: `pairFromCode` only resets when a *previous* pairing exists,
but "forget host" deletes that record; and the schema-version check cannot fire because both hosts are
schema 5. Fix per the user's ruling: **the mirror records its own hostId**; on mismatch, **archive** the
old mirror + queue to `<private>/archive/<oldHostId>-<ts>/`, then rebuild and full-pull. Archive is not
deletion — expose it in Settings, plus a manual "rebuild local copy" escape hatch.

## 三之二、批次 D（用户 `reply.md` 新增，**升级为必修**）· `LocalIp` 双端兜底 ✅ **已落地（2026-10-27，见 §三之三）**

**为什么升为必修**：复跑时它让整组同步测试卡了半小时，而且**目标用户群会普遍踩到** ——
「个体户店里装了监控、收银机、或者梯子/穿透工具，机器上可能有三四个虚拟网卡」（用户原话）。

**根因**：`LocalIp.choose` 的 `virtualMarkers` 名单是**穷举法**，`natpierce` 不在里面，
而 Windows 枚举顺序又在 `WLAN` 之前 ⇒ 规则 ① 命中隧道地址 `10.6.22.1`，手机 `http=000` 5 秒超时。

**修法（两条，缺一不可）**：

| # | 端 | 做法 |
|---|---|---|
| 1 | **主机** | `LocalIp.choose` 补「真网卡名优先」的正向规则（wlan/wifi/ethernet/以太网/无线/本地连接 优先），并把 `natpierce` 等已知隧道名加入 markers；**配对对话框把全部候选地址列出来 + 备注网卡名**，让用户能自己挑对的 |
| 2 | **手机** | 扫码页加「**手动输入地址**」入口（`192.168.x.x:17890` 或直接粘配对码文本）—— 当前**只有扫码、零兜底** |

**测试**：
1. `choose` 在「natpierce(10.6.22.1) + WLAN(10.102.43.94)」两种枚举顺序下都返回 WLAN；
2. 全部候选都是虚拟网卡时仍返回一个（不返回 null，既有行为不许退化）；
3. 手机端手动输入：非法格式给红字、合法格式能连上（widget 测试）。

> ⚠️ 与 A-2 的关系：**先修 host_id 身份判定（A-2），再修 IP 兜底（D）** ——
> 否则"手动填错 IP"会变成新的串账入口。用户原话也是这个顺序。

### English

Batch D is promoted to must-fix: the NIC picker is an enumeration-based heuristic that breaks for any
user running a tunnel/VPN adapter, and the phone currently has **no manual-address fallback at all**.
Fix both ends (positive "real NIC" ranking + list all candidates on the host; manual address entry on
the phone). Do **after** A-2, so a wrong manual IP cannot become a new cross-shop contamination path.

### 一、主机端：`LocalIp`（`packages/shensuanzi_host/lib/src/local_ip.dart`）

**根因比原判更具体**：`virtualMarkers` 是**穷举法**，`natpierce` 不在名单里，
而 `choose` 的规则 ① 是「私有网段 + 非虚拟」⇒ 隧道地址 `10.6.22.1` 直接命中。

| # | 改动 | 为什么 |
|---|---|---|
| 1 | 新增 `realMarkers`（`wlan` / `wifi` / `无线` / `以太网` / `ethernet` / `eth` / `本地连接`…）+ **正向规则**（真网卡名优先） | 黑名单天生补不全：用户装的下一个穿透工具（frp / ngrok / 公司 VPN）照样不在名单里 |
| 2 | `virtualMarkers` 补 30 个已知隧道 / VPN / 拨号名（`natpierce` / `pierce` / `ngrok` / `frp` / `openvpn` / `wireguard` / `wan miniport` / `pptp` / `l2tp` / `sstp` / `ikev2`…） | 已知的坑垫到最低优先级 |
| 3 | `choose` 改为 **`rank` 排序 + 取第一个**（排序逻辑唯一来源） | 从前是四段 for 循环，`choose` 与「候选列表」会各写一遍 ⇒ 必然漂移（纪律 18） |
| 4 | 新增 `NetAddressOption` + `LocalIp.detectAll()` / `rank()` | 让界面能把**全部**候选列出来（见下） |

**分档**（`rank`，数字越小越优先）：`0` 私有+真网卡名 / `1` 私有+非虚拟 / `2` 私有+虚拟 /
`3` 公网+非虚拟 / `4` 其余。同档保持枚举顺序（**分桶收集，不用 `sort`** —— Dart 的 `sort` 不保证稳定）。

⚠️ **虚拟判定必须优先于真网卡判定**：`vEthernet (WSL)` 的名字里含 `ethernet`，
先看正向名单就会把它当"真网卡"，把既有用例「WSL 的 172.x 不抢真网卡」弄红。

### 二、主机端：控制器 + 界面（猜错时的自救）

| # | 改动 | 说明 |
|---|---|---|
| 5 | `HostServiceSnapshot.addressOptions` + `hasAddressChoice` | 把候选摆出来 |
| 6 | `HostServiceController.selectAddress(ip)` | **只接受候选里的地址**：让用户随手填 IP 会把他引向「码看着正常、就是连不上」，比现状更难查。换地址**不用重启服务**（绑的是 `0.0.0.0`，地址只影响二维码内容） |
| 7 | 构造参数 `detectAddresses`（可注入） | ⚠️ **只注入了 `detectLocalIp` 时不做真扫网卡** —— 否则单测会摸真实网卡，候选列表随开发机变化 |

## 四、需要你裁的四个决策点（**已裁定 2026-10-25**）

### D1（F3）全退之后，还要不要显示「还欠客户退款」？

背景：`XS…-001` 货全退了，但 `XT…-003`（¥10.50）当时没退款；卡片只写
「已退货 −¥14.00 / 已全部退清 / 状态 已结清」，**一个字都没提还欠客户 10.50**。

| 选项 | 卡片怎么显示 |
|---|---|
| **甲** | 全退时保留一行「**还欠客户退款 ¥10.50**」，状态行不再写「已结清」（货都退了，"结清"没意义） |
| **乙** | 只删「已全部退清」那行，状态保留「已结清」，退款只在退货单上看 |

**✅ 裁定：甲**（2026-10-25，理由：「商品全退了，但钱没退，状态写『已结清』是自欺欺人」）。
（代码里 `document_detail_page.dart:341` 已把这个挂着当 #38 第二步。）

### D2（F10）单据导出要不要"恒全量"？

背景：筛「今天」导出 13 行，库里 18 张；漏的正是 3 张自动收付款 + 1 张退款 + 1 张拒收退货。
`document_dao.dart:256` 的注释写「导出恒全量，不跟随 includeDerived」，但实现跟随了。

| 选项 | 做法 |
|---|---|
| **甲** | 按注释办：导出恒全量（`includeDerived: true`），文件 18 行 |
| **乙** | 按实现办：改注释 + 改按钮文案，明说"派生单不导出"（对账永远少 5 张，**不推荐**） |

**✅ 裁定：甲**（2026-10-25，理由：「会计拿 CSV 去对账，少 5 张自动收付款单会直接导致对账爆炸」）。

### D3（F4）详情页的关联单，怎么处理才不会"困住用户"？

| 选项 | 做法 |
|---|---|
| **甲** | 关联单**不再跳转**，就地展开摘要（详情页只做"终点"） |
| **乙** | 保留跳转，但顶部加面包屑 / 「回到原单 XS…」 |
| **丙** | 只允许单向：原单 → 关联单；关联单里的入口不再下钻 |

**✅ 裁定：乙**（2026-10-25，理由：关联单是「证据」，不能删也不能展平（太长）⇒ 面包屑 /「返回原单」）。

### D4（F12）SnackBar 只是改短，还是换形态？

| 选项 | 做法 |
