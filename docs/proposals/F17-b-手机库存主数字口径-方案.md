## 一、现状：五个地方各取各的口径

以 `lib/src/ui/stock_page.dart` 为准（行号对应当前 `master`）：

| 位置 | 显示/计算什么 | 取的口径 |
|---|---|---|
| `:499` | `final int inStore = book - inTransit;` | **账面 − 在途**（权威） |
| `:503-504` | `negative` / `low`（决定颜色与「已超卖 / 低于安全库存」） | 同上 |
| `:267-269` | 列表排序（在店可售降序） | 同上（另有一份独立实现 `inStore(Product)`） |
| `:576` | **行内大字**（`'$inStore'`，`headlineSmall` + 加粗） | 同上 |
| `:600` | 小字「账面 N · 在途 M」 | 权威原值 |
| `:740` | `if (unsynced != 0 && delta != null)` → 渲染 `_StockDeltaLine` | **仅当有未同步时** |
| `:793 / :808` | 叠加行「≈ 台账 N + 未同步 ±K = 合计」 | 账面 + 未同步（**不减在途**） |
| `export_tables.dart:64` | 导出列「库存数量 / 在途 / 在店可售」 | 全部权威，**无未同步列** |

`hasFlow()`（`:257`）已经**把未同步算进"这一行该不该显示"**——也就是说，
隐藏逻辑早就承认了未同步，只有"数字本身"没承认。

### English

There are five places with their own convention. The headline number (`:576`), the
negative/low-stock test (`:503-504`) and the sort key (`:267-269`) all use
`book - inTransit` — the authoritative ledger only. The unsynced impact appears
solely in the small orange overlay line (`:740`). Note that `hasFlow()` (`:257`)
*already* counts unsynced when deciding whether a row should be visible: the
hiding logic acknowledges unsynced orders, the numbers do not.

## 二、问题：手机上「还能卖几件」被放在了小字里

真机证据（2026-10-26，release 0.6.5，测试可乐）：

| 时刻 | 大字 | 小字 | 叠加行 |
|---|---|---|---|
| 队列空 | **35** | 账面 37 · 在途 2 | 无 |
| 离线卖 1 件（待同步 1 条） | **35** ← 没变 | 账面 37 · 在途 2 | ≈ 台账 37 + 未同步 -1 = +36 |
| 同步后 | **34** | 账面 36 · 在途 2 | 无 |

中间那一行就是问题：**真实可售是 34，大字写着 35**。用户瞄一眼就走，多卖一件。
桌面端不会遇到（队列恒空），所以这个缺陷**只在手机上出现**，而手机恰恰是
"站在货架前、要立刻决定还能不能卖"的那一端。

### English

On the phone, after one offline sale, the headline still reads 35 while the real
sellable quantity is 34. The desktop never hits this (its queue is always empty),
so the defect is mobile-only — and mobile is exactly where the user stands in front
of the shelf deciding whether one more can be sold.

## 三、三个选项

### 甲（推荐）：手机壳主数字改成**估算合计**

- 大字 = `(book + unsynced) - inTransit`；有未同步时前缀 `≈`（`unsynced == 0` 时与现状**逐字相同**）。
- 小字「账面 37 · 在途 2」保留 —— 它是"这个数字怎么来的"的依据。
- 叠加行改成**完整算式**（见 §五·4）。

### 乙：主数字不动，把「≈」行提到**商品名下方**

- 只改渲染顺序：把 `_StockDeltaLine` 从行尾挪到名称块正下方。
- 改动最小，但**仍是两个数字并列**，用户还是可能只读大字。**治不了根**。

### 丙：不动，只在文档里写清口径

- 承认"大字 = 账面 − 在途，未同步看小字"，写进 `docs/ui_principles.md`。

| | 甲 | 乙 | 丙 |
|---|---|---|---|
| 用户第一眼看到的数字对不对 | **对** | 不对（要靠小字） | 不对 |
| 改动面 | 4 处 + 测试 | 1 处 | 0 |
| 桌面是否受影响 | **不受影响**（见 §四） | 不受影响 | — |
| 风险 | 大字要带 `≈`，否则像确定值 | 低 | 缺陷保留 |

### English

Option A (recommended): on the mobile shell the headline becomes
`(book + unsynced) - inTransit`, prefixed with `≈` whenever `unsynced != 0`.
Option B only moves the overlay line under the product name — two numbers side by
side, the user still reads the wrong one first. Option C documents the current
convention and leaves the defect in place.

## 四、为什么「与桌面不一致」**不是**代价

提案里最容易吵的一点，这里先算清：

- 桌面的 `stockDelta == null`（`app.dart` 里 `mirror == null` ⇒ 桌面恒 `null`）；
- `_StockRow.unsynced` 因此恒为 `0`；
- 甲 的条件是 `unsynced != 0` ⇒ **桌面上这条分支永远走不到，输出与今天逐字相同**。

⇒ 甲 不是"两端分叉"，而是"**只有存在未同步的那一端，数字才变准**"。
真正的口径分歧（账面对不对得上）由**导出**承担，导出保持权威口径（§八）。

### English

The desktop always has `stockDelta == null`, hence `unsynced == 0`, hence the new
branch never executes there — output is byte-identical to today. Option A does not
split the two ends; it only makes the number correct on the end that actually has
unsynced orders. Ledger reconciliation stays with the export, which keeps the
authoritative convention.

## 五、甲必须**一起**改的四处（少改一处就自相矛盾）

### 1. 大字（`:576`）

```dart
final int inStore = (book + unsynced) - inTransit;   // 原：book - inTransit
// 显示：unsynced != 0 ? '≈ $inStore' : '$inStore'
// 并挂 Key('stock-instore-${product.id}') —— 现在没有 Key，测试只能按文本找
```

### 2. 负 / 低判定 + 颜色 + 文案（`:503-510`）

`negative` / `low` / `mainColor` / `notice` 全部改用新 `inStore`。
否则会出现「大字写 34（低于安全库存 5）却仍显示黑色、不报补货」——
**数字和警告必须同一个口径**。

### 3. 排序（`:267-269`）

```dart
int inStore(Product p) =>
    (book[p.id] ?? 0) + (unsyncedByProduct[p.id] ?? 0) - (inTransit[p.id] ?? 0);
```

否则列表按"账面"排、显示按"合计"排，用户看到的是**乱序**（例：A 账面 10 卖光 10 件 ⇒ 显示 0，却排在显示 1 的 B 前面）。

### 4. 叠加行文案（`:808`）—— 现在是**算式错**的

现状：`≈ 台账 37 + 未同步 -1 = +36`，但大字（甲）是 **34**（36 再减在途 2）。
两个数字并列却对不上，比不显示更糟。改成完整算式：

```
≈ 台账 37 + 未同步 -1 − 在途 2 = 34
```

`inTransit == 0` 时省掉「− 在途 0」这一段（否则是噪音）。点开拆解的内容不变
（仍按单据列出 contributors）。

### English

Four changes must land together: the headline number, the negative/low-stock test
plus colour and message, the sort key, and the overlay formula — which is currently
*arithmetically inconsistent* with the headline (it omits `inTransit`). Fixing only
the headline produces a row whose big number and overlay disagree.

## 六、边界情况（逐条过）

| 场景 | 甲 的表现 | 说明 |
|---|---|---|
| `unsynced == 0`（桌面 / 已同步） | 与今天**逐字相同**，无 `≈` | 桌面零回归 |
| 负库存（合计 < 0） | 红色 + 「已超卖，尽快补货或核对账目」 | 判定跟着合计走 |
| 低库存（合计 ≤ 安全库存） | 橙色 + 「低于安全库存 N，该补货了」 | 同上 |
| 期初待同步（`openingPending`） | 大字**不变**，仍显示「期初 N（瓶）待同步」提示行 | `stocktake` 的 delta 客户端**算不出**（`stock_delta.dart:39`），甲不改变这一点；`≈` 前缀已表明"这是估算" |
| 在途 > 0 | `− 在途 N` 进算式 | 与页头「在店可售 = 账面 − 在途」的说明一致 |
| 多条离线单 | 汇总成一个数（`unsyncedDelta()` 已按商品合并） | 点开仍逐单列出 |
| 停用商品 | 列表不显示，导出仍含（AF-12） | 不受影响 |
| 搜索 / 「显示全部」开关 | 不受影响（`hasFlow` 已含未同步） | — |

### English

Edge cases: zero unsynced is byte-identical to today; negative and low-stock tests
follow the combined number; the opening-stock pending note stays as-is because a
`stocktake` delta cannot be computed on the client; in-transit enters the formula
explicitly; multiple offline orders collapse into one number but still expand per
document; disabled products and the search/`show-all` toggles are untouched.

## 八、明确**不做**的事

1. **不改导出**（`stockExportTable`）—— 导出是"拿给会计对账"的权威口径，
   加一列「未同步」只会让对账更难；且手机上导出本来就是排查用途。
   若将来要加，应是**新增一列**（字段只增不删），不是改现有列。
2. **不改 core**（`StockDelta`）—— 它已经算对了，问题在"哪个数字放到大字上"。
3. **不改桌面** —— 见 §四。
4. **不动「在店可售 = 账面 − 在途」这条公式本身** —— 它另有一条"描述与实现不一致"
   的遗留（`query_dao.dart:63` 的注释，纪律 17），与本提案无关，不顺手改。

### English

Out of scope: the export keeps the authoritative convention; `StockDelta` in core is
already correct; the desktop is untouched; and the `book - inTransit` formula itself
stays (its doc/code mismatch is a separate item).
