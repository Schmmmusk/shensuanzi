## 一、背景与范围

Q5 从 30 项 P2 里只挑了三项，另外两项随 UI 审查的批 1–3 已全部落地，
只剩**对比度**与**点击区**。范围刻意收窄：

- **只做两处**：概览页负库存告警的 `Colors.red`；两处 < 44px 的常驻点击区

- **不做**（Q5 明确留 0.7）：报告 §2.5 其余 P2（橙色提示三套外观统一、
  选择器弹层关闭入口、导航 60px 兜底、手机三态条等）。
- **不动业务逻辑、不动 schema**；版本随 **0.6.2** 发布，不单独 bump、不热修。

English: This proposal closes the last two of the three P2 items selected by ruling Q5
(the third, "clear filters", shipped with batch 3 item 16). Scope is deliberately narrow:
one contrast fix (overview negative-stock warning) and two undersized tap targets
(unit chips in the product form, the cost-basis info icon on the stock page).
Everything else in P2 stays deferred to 0.7 per Q5. No business-logic or schema changes;
ships with 0.6.2 per Q6 (no hotfix, no version bump of its own).

## 二、现状（实测）

### 2.1 对比度：`overview_page.dart:398-406`

负库存告警是一行 15px 文字，颜色写死 `Colors.red`：

```dart
if (negativeStock > 0)
  Text(
    '负库存 $negativeStock 种 —— 可能是没录期初或超卖，点「库存」看看',
    style: const TextStyle(
      height: 1.7,
      fontSize: 15,
      color: Colors.red,        // ← #F44336
    ),
  ),
```

- 背景 `#FAFAFA` ⇒ 对比度 **≈ 3.53:1**，低于 `ui_principles.md` §二
  「次要文字 ≥ 4.5:1」。
- 全仓 `grep -rn "Colors.red" lib/` **只有这一处** —— 收拾它不会连带别处。
- 同页 `:231` 等处已经在用 `theme.colorScheme.error`，本项目**事实上**的错误色口径
  就是它；`app_colors.dart` 文件头也明写「错误色不在这里 —— 用 `Theme.colorScheme.error`」。
  这行 `Colors.red` 是**唯一没归队**的。

### 2.2 点击区 A：`product_form_dialog.dart:360-376`（单位 chips）

建档表单「单位」框下方一排 `ActionChip`（14 个常用单位 + 1 个 `其他 ▾`）。
M3 `ActionChip` 默认高约 **32px** < `ui_principles.md` §二「按钮最小点击区 44 × 44」。

⚠️ **SDK 实测（Flutter 3.11，`chip.dart:1296`）**：`materialTapTargetSize` 的
`padded` 档只作用于 chip 的**删除图标子目标**（`_EnsureMinSemanticsSize` 包着的那块），
**不扩大 chip 主体的点击区**（主体就是包着 Material 的那个 `InkWell`，范围 = chip 自身边界）。
⇒ 「给 chip 设个 `materialTapTargetSize` 就行」这条路**走不通**，别再试。

### 2.3 点击区 B：`stock_page.dart:593-615`（成本口径 ⓘ）

「成本（均价）」旁的 ⓘ 是 `Tooltip(triggerMode: tap)`，child 是
`Row(Text + Icon(size: 14))`，整行高约 **22px** < 44。手机 / 鼠标都能点，
但目标太小 —— 这正是 `ui_principles.md` §1.3「常驻控件必须好点」要防的。

English (现状): The overview negative-stock warning hardcodes `Colors.red` (#F44336),
≈3.53:1 on the #FAFAFA background, under the 4.5:1 secondary-text floor — and it is the
only `Colors.red` left in `lib/`; the rest of the app already uses `theme.colorScheme.error`.
The unit chips in the product form are M3 ActionChips ≈32px tall (floor: 44×44); the SDK's
`materialTapTargetSize.padded` only pads the delete-icon sub-target, not the chip body, so it
cannot fix this. The cost-basis ⓘ on the stock page is a tap-triggered Tooltip whose child row
is ≈22px tall. Line numbers re-read on 2026-10-23.

## 三、方案（三项，各带甲 / 乙）

### 3.1 对比度 ⇒ 推荐**甲**

**甲**：`Colors.red` → `theme.colorScheme.error`。同时把 `const TextStyle` 的 `const` 去掉
（颜色来自主题，不再是编译期常量）。

- 实测（Flutter 3.11 探针）：`ColorScheme.fromSeed(seedColor: 0xFF2F6FA8)` 下
  `error = #BA1A1A`，对 `#FAFAFA` ≈ **6.19:1**，过 4.5:1 有余量。
- 值**不写死**：SDK 基线色将来若变，我们跟着变，不会漂（硬编码 #BA1A1A 才会）。
- 与全仓错误色统一，`ui_principles.md` §一「红只留给真错误」的口径不变
  （负库存告警本来就是真告警，用错误色合理）。

**乙**：在 `AppColors` 加一个深红常量。**不推荐** —— `app_colors.dart` 文件头明说
错误色不走那里；再加一个颜色来源等于自己拆自己的台。

### 3.2 单位 chips ⇒ 推荐**甲**

**甲**：每个 `ActionChip` 包一层 `ConstrainedBox(constraints: BoxConstraints(minHeight: 44))`。
chip 视觉长高到 44，点击区（= chip 自身边界）随之达标，**不存在点击区重叠**
（不同于「在外边包 Padding」—— 那不扩大点击区，还会和邻座 chip 的点击区互吃）。

- 副作用：表单弹窗总高 +12px 左右；`Wrap` 行数不变（宽度不受影响）。
- 大字号护栏（`product_form_dialog_test` 已有 2.0 档用例）复跑确认不溢出。

**乙**：自绘 `InkWell + Container(44)` 替换 ActionChip。**不推荐** —— 代码量翻倍、
要自己复刻 chip 的水波纹与禁用态，收益为零。

### 3.3 成本口径 ⓘ ⇒ 推荐**甲**

**甲**：`Tooltip` 的 child 从裸 `Row` 换成
`SizedBox(height: 44, child: Center(child: Row(...)))` —— **视觉不变**（行仍居中），
点击区变成 44 高。给这个 `Row` 加 `Key('stock-cost-info')` 供测试定位。

**乙**：把 Tooltip 触发面扩大到整行「成本（均价）+ ⓘ + 金额」。**不推荐** ——
金额那片已经有别的交互语义（负值红色联动），触发面混在一起会让 tooltip
在用户点金额时也弹出来，反而扰民。

English (方案): ① Contrast: switch to `theme.colorScheme.error` (measured #BA1A1A ≈ 6.19:1,
not hardcoded so it tracks the SDK baseline); drop the now-impossible `const`.
② Chips: wrap each ActionChip in a `ConstrainedBox(minHeight: 44)` — the chip grows to 44 so
its own bounds become a legal target, with no overlap issue that external padding would cause.
③ ⓘ: wrap the Tooltip child in `SizedBox(height: 44, child: Center(...))` — same visuals,
legal target; add `Key('stock-cost-info')` for the guard test.

## 四、机械护栏（先立护栏，再改实现）

照批 3 第 18 条的成法：**先写会红的断言，再改代码**，三项各一条：

| 护栏 | 落点 | 断言 |
|---|---|---|
| 错误色归队 | `overview_page_test.dart`（扩展现有 `#32`） | 负库存那行的 `color == theme.colorScheme.error` 且 `!= Colors.red` |
| chips ≥ 44 | `product_form_dialog_test.dart`（新用例） | `tester.getSize(find.byType(ActionChip).first).height >= 44` |
| ⓘ ≥ 44 | `stock_page_test.dart`（新用例） | 按 `Key('stock-cost-info')` 取 `getSize(...).height >= 44` |

**反向验证**（交付前必做）：把三项实现分别临时回退，对应护栏必须见红 ——
抓不回退的护栏等于没写。

English (护栏): Three guard assertions, written before the fixes (red first, then green):
the overview warning's color equals `colorScheme.error`; every unit chip renders ≥44px tall;
the cost-info row is ≥44px tall. Each guard is reverse-tested by temporarily reverting the fix.

## 五、要你裁的三件事

| # | 决策点 | 甲（推荐） | 乙 |
|---|---|---|---|
| ① | 对比度 | `theme.colorScheme.error`（≈6.19:1，跟 SDK 基线不漂） | `AppColors` 加深红常量 |

English: Three decision points; the lazy path is "take 甲 (recommended) on all three" —
each is self-contained with no follow-up questions.
