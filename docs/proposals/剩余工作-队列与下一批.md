## 三、下一批建议：**#34① 往来方流水 · 超大档溢出**

### 中文

**根因（已定位，不需要再猜）**

`PartyFlowPage` 用 `LayoutBuilder` 只做了一件事：**窄屏**（`maxWidth < 600`）时
`MediaQuery.withClampedTextScaling(maxScaleFactor: 1.15)` + 换 `_NarrowFlowCard`。
**桌面宽屏走 `_WideFlowTile`，而这个 tile 从没做过限幅或重排**：

```
ListTile(
  title:   Row[ Expanded(单号, w600), 类型 ]
  subtitle: 日期
  trailing: 17sp「还款 -¥260.00」
)
```

`ListTile` 的 `trailing` **不参与收缩**：字号 2.0 时它是 34sp 宽，加上单号（`XS20261012-008`）
和类型，宽屏也放不下 ⇒ RenderFlex overflow（真机红黄条 + 日志）。

**两个候选改法**

| 案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **甲（推荐，已落地）** | 把 `_WideFlowTile` 的 `ListTile` 换成**自绘两行**：`Row[ Expanded(左列: 单号 + 类型·日期), 右列金额（**不包 `Expanded`**，自然占内容宽） ]` —— 与单据列表页（#26② 已落地）**同一套布局思路** | 一次改，**所有字号**都不溢出；左列可省略号，金额永不截断 | 行高从「ListTile 三行」变成「自绘两行」，需目视对齐一次 |
| 乙 | 只在 `textScaler > 1.3` 时切到已有的 `_NarrowFlowCard` | 改动最小（一个 if） | 「1.3」是魔数；1.2 档仍可能挤（只是没到溢出阈值） |

**我建议甲**：`#26②` 已经用「Expanded + 单行省略 + 右列 intrinsic」把同类问题在单据列表上修过一次，
两处用**同一套布局**，以后不会各自漂（纪律 18）。

**测试（先红后改，已落地）**

1. **widget 测试**（`test/parties_page_test.dart` 的 `#34①` 组）：`textScaler = 3.0`、窗口 800 宽
   ⇒ 断言 `tester.takeException()` 为 `null`；
   ⚠️ **实测：2.0 倍在 600 / 800 宽下并不溢出**（绿），**3.0 倍**才 `overflowed by 13 pixels`
   —— 所以断言定在 3.0（按 2.0 写会得到一条「改前就绿」的假测试）；
2. 同一测试断言**金额仍完整可见**（`find.textContaining('¥260.00')`）——防止「用省略号把金额截掉」的假修；
3. 另加一条**常规字号**用例（单号 / 类型·日期 / 金额三样都在）—— 防把好的改坏；
4. 反向灵敏度：`git stash` 单文件退回 `ListTile` ⇒ 第 1 条必红（已做）。

**边界（明确不做）**

- **不改**整页的窄屏限幅（`1.15` 是 §二 的裁定值，动它会波及所有手机页）；
- **不动** `_NarrowFlowCard`（它已验证过，且窄屏逻辑与本次无关）；
- 若同一批发现**其它页**在 2.0 下也溢出 ⇒ **只登记不顺手改**（纪律 18 的「先 grep 同款」在这里指
  「先确认是不是同一类布局」，不是「把全仓 UI 都扫一遍」）。

### English

**Root cause (located).** `PartyFlowPage` only clamps text scaling and swaps in `_NarrowFlowCard`
**when width < 600**. Desktop keeps `_WideFlowTile`, whose `ListTile` has a 17sp `trailing` that
**does not shrink**; at 2.0 text scale (34sp) it collides with the doc number ⇒ RenderFlex overflow.

**Option A (shipped)**: replace the `ListTile` with a hand-built two-column row —
`Expanded(left: doc no + type · date)` + an amount column that is **not** wrapped in `Expanded`
(so it takes its natural width) — the **same layout idea already shipped in the documents list (#26②)**.
Fixes every text scale; the amount is never truncated. (Note: Flutter has no `intrinsic` property on
`Row`; "natural width" is simply "don't wrap it in `Expanded`".)
**Option B**: switch to `_NarrowFlowCard` only when `textScaler > 1.3` — smaller diff, but the
threshold is a magic number and 1.2 can still be cramped.

**Tests (red first)**: a widget test at 1200px width and `textScaler = 2.0` asserting
`tester.takeException() == null` and the amount still visible; reverse-sensitivity by reverting to
`ListTile`.

**Out of scope**: the narrow-screen clamp value (1.15, already ruled), `_NarrowFlowCard`, and any
other page found overflowing (register only).

## 五、顺序建议（我按这个排）

```
下一批：34①（0.5 天，无依赖）
  ↓
schema 批：24 + 56 + 43②（1.5–2 天，一次迁移）
  ↓
```

理由：**先修用户看得见的**（34①），再做**要动库的**（一次付清迁移代价），
然后补**防止再犯的工具**（45），最后做低频项。

### English

Fix what users can see first (34①), then pay the migration cost once (24+56+43②),
then invest in the guard that prevents the next "only one page changed" (45), then the low-frequency items.
