# 提案区（`docs/proposals/`）

> **这个目录解决一件事**：让「**这份文档在说什么状态**」可以从**目录结构**上看出来，
> 而不是靠读正文猜（`docs/reply.md` 二·越界 1）。
>
> 来源：2026-10-01 文档越界审查；**三分法在 2026-10-02 审查时补全**（见下）。

## 一、三分法（三条线，互不重叠）

| 状态 | 去处 | 标记 |
|---|---|---|
| **待裁定**的提案 | **本目录**（一提案一文件） | `🔴 待裁定，未动实现` |
| **已裁定 + 已落地**的裁定与记录 | 主台账 `reply_review.md` 的活跃节 | `✅ 已落地` / `裁定` |
| **已裁定 + 已完成的「提案」**（历史过程记录） | **`reply_review_archive_v3.md`** | `📦 已归档` |

**第三条线是 2026-10-02 补的。** 在那之前，「已裁定 + 已完成的提案」被夹在
「提案区」和「台账」之间**无处安放** —— 而主台账头部自己声明「本文件是**活跃的**
裁定与落地台账」，把它留在里面会让读者以为「它还在等什么」。
`§AL` 就是第一个住户（归档前它一直挂在台账里）。

> **判据**（来自同一份审查）：**文件是否在做它自己声明的事**。
> 台账声明「活跃」⇒ 已完成的提案就不该在里面。

## 二、规则

1. **提案不占主台账的 §编号**：它用自己的文件名与编号
   （如 `AU-实地测试四项问题.md`）。
2. ⚠️ **编号不丢**：**编号必须保留在文件名里** ——
   别处（台账、`docs/reply.md`）会引用 `§AU` / `§AU·四`，改名成
   `实地测试四项问题.md` 会让所有引用**断线**。
3. **裁定后回主台账：保留原编号，不重新分配。**
   台账是「**接管**」这个编号（§AU 仍叫 §AU），不是给它一个新号 ——
   重新分配编号同样会断引用。
4. **更新纪律**：提案被裁定前**只在本目录改**；裁定后**只往台账加**。
5. 提案里引用的 `§编号` **一律指 `reply_review.md` 的编号**（不是本目录的）。
