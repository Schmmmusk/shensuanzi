### ⑤ 电脑端看到手机已同步的结果

| 选项 | 做法 | 代价 | 评 |
|---|---|---|---|
| **甲（推荐）** | **让推送落到界面**：`SyncServer` 应用成功后（**落库成功条数 > 0**）经 `HostHttpServer` → `HostServiceController` 暴露一个「主机刚收下 N 条」的回调 / 版本号；`app.dart` 订阅 ⇒ `setState` ⇒ 当前页重读。<br>同时把设置页那份 `_snapshot` 从 `late` 快照改成**按需重取**（否则「最近连接」仍是死的） | 动 `shensuanzi_host`（+1 个可选回调）+ 根 `app.dart`（订阅）+ 1 处 UI；**不改 schema、不改协议** | 判据「**立刻**」成立；用户不需要知道「切页才刷新」这件事 |

**⚠️ 甲 的三个已知风险（先摆出来）**：
1. **重建时机**：推送应用发生在 HTTP handler 的异步流程里 ⇒ 必须**只 `setState`、不在 build 期间调**（同一 isolate，安全；但要判 `mounted`）。
2. **别过度重建**：若挂在「任何认证过的请求」上（现有 `onAuthenticated`），**纯 pull 也会触发重建** ⇒ 宁可**多一个精确回调**（落库条数 > 0），也不要每 30 秒重建一次界面。
3. **不能承诺「立刻」之外的东西**：手机离线时**没有任何东西可同步**，这条只解决「已经传上来了，电脑却看不到」。

## 五、风险与边界（诚实说明）

- **① 的「同名」判据必须含停用档**（`findByNameIncludingInactive`）：只看启用中的会漏掉
  「停用但还欠钱的同名」—— 那正是 OBS-05 修过的洞（`party_service.dart:72-85`）。
- **① 的提示不能变成拦截**：同名追加身份是**既有合法设计**（Z-4「绝不出现两条同名」），
  提示只解释「会发生什么」，**不许**弹「已有同名，确定吗」。
- **② 是「列不列出来」，不是「删档」**：开关关掉时停用行只是不显示，
  **余额不等于消失**（尤其是裁甲之前的账户页，见 §二·② 的口径问题）。
- **③ 只改文案**：判定条件一个字不动（`recordedDueCents > 0`）—— 改判定会动到
  §AY·四「多付 = 找回，不算欠款」的既有裁定。
- **④ 不做「自动把「顾客给了」当收款」**：那是 §AJ·AI-4 的既有裁定，
  要动得先重裁（本提案不碰）。提示的措辞要**说清「现在会发生什么」**（整单赊账 ¥30.00），
  不能只说「填错框了」。
- **⑤ 甲 不改同步协议、不改 schema**：只是「谁在什么时候重建界面」；
  若你担心重建打扰正在开单的人，我们可以把重建**限定在「当前页不是开单页」**时执行
  （备选，见 §四·10 复述时点出来）。
- **⑤ 乙 是「承认现状」而不是「修好」**：若选乙，则 `desktop_acceptance.md:108` 的
  「立刻」**必须**改掉，否则是第 41 条那类「我自己写的假判据」重演。
- **不承诺测试全绿**：本仓根 `lib/` 的编译/测试门禁**最终以你复跑为准**（`testing.md` §L）——
  我交付时会真跑 core / app / host 三包，根侧如实报「我跑了什么」，不声称「界面已验」。
