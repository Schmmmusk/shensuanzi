# 裁定：左侧常驻导航

## 一、理由

**1. 垂直空间比水平空间贵**

神算子的核心页面全是**表格**——商品列表、库存、单据、往来方。表格需要的是**高度**，每多显示一行都直接减少一次滚动。

顶部标签页把最贵的垂直空间吃掉 40-60px，而且**行数越多越亏**。左侧导航占的是水平空间，而内容区的宽度在 1080p 下完全够用。

**2. 标签页多了会退化成"更多"菜单**

神算子的功能至少有 8-10 项：销售开单、采购入库、商品、库存、单据、收款、往来方、账户、设置、备份。

顶部标签页一超过 6 个就开始折叠——折叠后就是**隐藏入口**，而中老年用户不会去点"更多"。这直接违背"所有功能必须有常驻可见的入口 + 文字标签"的原则。

左侧导航加功能不需要重排布局，加 20 项都能列完。

**3. 桌面软件的认知范式**

微信、钉钉、企业微信、几乎所有 ERP 和 POS——左边一列、右边内容。中老年用户**见过这个模式**，不需要学习。

顶部标签页是**浏览器心智**，属于"看多个文档"，不是"在多个功能间切换"。

**4. 图标 + 文字的稳定组合**

左侧导航天然容纳"图标 + 文字"这一对组合（顶部标签页做这个会很挤）。用户扫一眼就能定位，不需要悬停。

## 二、设计细节

### 宽度与分组

```
┌──────────────┬──────────────────────────────┐
│              │                              │
│  🧾 销售开单  │                              │
│  📦 采购入库  │                              │
│              │                              │
│  ─────────   │                              │
│              │                              │
│  📋 商品      │         内容区               │
│  🏪 库存      │                              │
│  📄 单据      │                              │
│  👥 往来方    │                              │
│  💰 账户      │                              │
│              │                              │
│  ─────────   │                              │
│              │                              │
│  ⚙️ 设置      │                              │
│  ❓ 帮助      │                              │
│              │                              │
└──────────────┴──────────────────────────────┘
   220px
```

**分组逻辑**（不是随意排）：

| 组 | 项 | 为什么这样分 |
|---|---|---|
| 高频动作 | 销售开单、采购入库 | 每天几十次，放最上面，肌肉记忆 |
| 数据查询 | 商品、库存、单据、往来方、账户 | 按"找什么"组织，符合日常语言 |
| 系统 | 设置、帮助 | 低频，放底部 |

**用分隔线和间距分组**，不用嵌套折叠——中老年用户不会展开。

### 高亮与位置感知

中老年用户对"我在哪里"感知弱，必须给强信号：

```
当前页：左侧背景变色 + 左侧 3px 竖条 + 文字加粗
        （三重信号，不是只变颜色——色弱用户也能感知）
```

顶部加**面包屑**：`销售开单 > 已保存`。开完单后用户知道自己在哪、刚才发生了什么。

### 缩放兼容

界面缩放 125% / 150% / 200% 时，导航宽度**按比例缩放**，但**文字不换行**：

- 220px × 150% = 330px
- 如果窗口宽度不够，导航**可折叠为 60px 只留图标**——但这是**高级选项**，默认折叠只对 200% + 小窗口生效

**绝不做**：图标 hover 才显示文字（中老年用户不会悬停）。

### 折中选项

给高级用户（或小屏）一个**"紧凑模式"**开关：导航宽度从 220px 缩到 160px，图标变小、文字保留。默认关闭。

## 三、一个例外：开单页的"沉浸模式"

销售开单和采购入库**可以占用整个右侧**，不显示面包屑、不显示列表——因为开单是一个**连续的动作流程**，不是"浏览一个列表"。

```
┌──────────────┬──────────────────────────────┐
│  🧾 销售开单  │  ← 高亮                      │
│  📦 采购入库  │                              │
│              │  [ 客户：张三 ▾ ]  [ 日期 ]  │
│  ─────────   │  ─────────────────────────   │
│              │  商品          数量   单价    │
│  📋 商品      │  ─────────────────────────   │
│  ...         │  苹果          10    5.00    │
│              │  [+]                         │
│              │                              │
│              │  合计：50.00                 │
│              │  收款：[ 现金 ▾ ] 50.00     │
│              │                              │
│              │        [ 取消 ]  [ 保存 ]    │
└──────────────┴──────────────────────────────┘
```

**左侧导航仍显示**——用户随时可以跳走（比如发现商品没建档，切到"商品"页加一个再回来）。但**开单页本身不显示面包屑和工具栏**，把注意力集中在"这一单"上。

## 四、不要做的事

| 反模式 | 为什么 |
|---|---|
| 图标-only 导航（hover 显示文字） | 中老年用户不会悬停 |
| 汉堡菜单 ☰ | 不懂 |
| 折叠二级菜单 | 不会展开 |
| 顶部标签页 | 空间浪费 + 会退化成"更多" |
| 自定义拖拽排序导航 | 用户不会去调，反而会弄乱 |
| 深色主题作为默认 | 强对比，中老年用户看久了累 |

## 五、一句话

**左侧常驻导航，分组清晰、图标 + 文字、高亮给三重信号。** 顶部标签页看似现代，实际上是在用最贵的垂直空间换最不需要的水平空间，而且一旦功能超过 6 项就会退化成隐藏菜单——恰好踩中中老年用户最大的使用障碍。
