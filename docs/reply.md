## 二、必须修正的问题

### 1. 待裁定项 3 的金额口径有舍入陷阱【必须改】

提案推荐：

> 退货金额默认 = **原单行派生单价 × 退货数量**，允许改价

**问题：`unit_price` 是派生值**（`round(amount / quantity)`），用它乘退货数量会引入舍入差。

举例：

- 原单行：3 箱 × ¥250/箱 = 75000 分，`quantity = 36`，`unit_price = round(75000/36) = 2083`
- 退 3 瓶：`3 × 2083 = 6249`
- 但按比例：`75000 × 3/36 = 6250`

**差 1 分。多次退货会累积。**

**建议改为与成本分摊同构的累计比例法：**

```text
原单行金额 = 原单该行的 amount
累计退货量 = 已退量 + 本次退货量
累计应退额 = round_half_up(原单行金额 × 累计退货量 / 原单行数量)
本次应退额 = 累计应退额 − 已退金额
```

这样多次退货之和**精确等于**应退总额，与 R-11 成本分摊同一哲学。

**同时要处理 `discount_amount`**：如果原单行有让价，退货金额应按比例回退让价部分，而不是按派生单价。累计比例法天然处理这一点。

**注意**：这与「允许改价」不冲突——默认值是比例法算出的，用户可以手动改。但默认值必须是精确的，不能用派生单价。

### 2. 拒收场景：原送货单的状态没写【必须补】

提案说：

> 送货单额外显示「客户拒收（整单退回）」（= 全量 `sale_return` ref delivery）

**但没写拒收后，原 `delivery` 单的 `status` 怎么办。**

看 `data_model.md` §3.1：

- 送货状态机：`in_transit → delivered → settled`
- 动作只做单向终态转变
- `cancelled` 在枚举里，但没写什么时候用

**拒收应该把 `delivery` 置为 `cancelled` 吗？**

- 如果置 `cancelled`：状态机清晰，但这需要一个新的状态转变路径（`in_transit → cancelled`），R-3 只定义了 `mark_delivered`。
- 如果不置：送货单停在 `in_transit`，永远不收口，在途视图会永远把它算进去。

**这是一个必须裁定的缺口。** 建议：

> **拒收时，主机在同一事务内把原 `delivery` 置为 `cancelled`**（新增一个规则内部的状态转变，不走 `documentAction`，因为它是 RULE-007 的副作用，不是独立动作）。

**否则「在途视图」会把已拒收的货一直算在在途**，低库存告警会失真。

---

### 3. 退货行的 `entry_*` 字段处理未明确【必须补】

v3 五列已落地，`document_lines` 包含 `entry_quantity` / `entry_unit` / `discount_amount`。

**退货行也是 `document_lines`，必须走同一口径。**

提案说「行（productId + 本次退货数量）」—— 没提单位切换。

**问题**：原单按箱录入，退货可以按瓶退吗？如果可以，`entry_unit` 怎么填？

**建议明确：**

> 退货行沿用原单行的 `entry_unit`（不允许切换单位）—— 退货是针对原交易的冲减，按原交易的单位退最自然。`entry_quantity` = 本次退货数量（按原单位），`quantity` = `toBaseQuantity(entry_quantity, entry_unit)`。
>
> `discount_amount`：退货默认 0，允许手动填（退货让价 = 退少一点）。

**这条要写进 R1 的草稿校验里，否则实现者会各自解读。**

---

### 4. UI 缺少确认步骤【建议补】

退货是**重大且难以逆转**的操作。按 `Agents.md` 4.3：

> **弹窗只留给重大 / 危险 / 不可逆操作**

退货符合这个标准。**建议保存前给一个确认对话框**，写清「将退 X 件、金额 Y 元、退款账户 Z」，用户确认后才提交。

**注意**：这不是「不拦人」的内联提醒，这是真正的危险操作确认。与「填多了自动折算找零」的场景不同——那个是用户意图明确、只是数值算错；退货是**会改变历史交易**的操作。

---

### 5. 立即退款金额约束未在草稿层提【建议补】

RULE-007 约束：

> `SUM(immediate_payments.amount) ≤ sale_return.total_amount`

R1 说「立即退款（账户 + 金额，可选）」，但没写草稿层怎么保证这个约束。

**建议**：与 `SaleDraft.recordedPaymentCents` 同构，`ReturnDraft` 在草稿层封顶到 `total_amount`，超出部分按「找零」口径处理（与 RULE-002 同构）。
