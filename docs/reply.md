# 两个裁定的意见

## 一、数据目录：同意"用户指定"，但需要保护机制

你的顾虑是具体的，不是理论风险——**清理类软件扫 `%LOCALAPPDATA%` 是常规操作**，而"经营数据"和"缓存"在那个目录里长得没有区别。Nova 越勤奋，神算子越危险。

但"用户指定"如果做得太裸，也有自己的坑：

| 天真实现 | 现实后果 |
|---|---|
| 首次启动弹目录选择框 | 中老年用户会懵——"选哪里？C 盘还是 D 盘？我不知道啊" |
| 路径只存在内存 | 重启后忘了路径 → 找不到数据 → 以为数据丢了 |
| 允许任意路径 | 有人选到 U 盘 / OneDrive 同步目录，拔盘后打不开，或 SQLite 被同步冲突损坏 |
| 允许选 `C:\Program Files` | 无写权限，创建失败，报错看不懂 |

### 建议：默认 + 覆盖 + 校验

**首次启动的默认值**（不弹框，直接给出，可改）：

```
D:\神算子数据\        ← 存在非系统盘时优先
否则 C:\Users\<你>\神算子数据\
```

**为什么默认在非系统盘**：
1. 重装系统不丢数据（个体工商户的最大杀手）
2. 绕开 `%LOCALAPPDATA%` 的清理风险
3. 备份到 U 盘更顺手

**为什么不默认 `文档\神算子\`**：OneDrive 会同步它，SQLite 在同步盘上运行有真实的损坏风险。这一条要写进 README。

**首次启动的 UI**（向导第 1 步）：

```
┌─────────────────────────────────────────────┐
│  数据存放在哪里？                            │
│                                             │
│  建议放在非系统盘，重装系统不会丢。          │
│                                             │
│  📁 D:\神算子数据\                          │
│     D 盘剩余 128 GB                         │
│                                             │
│     [ 更改位置 ]   [ 使用这个位置 ]          │
│                                             │
│  ⓘ 不要放在 U 盘或网盘同步文件夹。          │
└─────────────────────────────────────────────┘
```

**路径校验**（选中后立刻检，不合格直接拦）：

| 情况 | 处理 |
|---|---|
| 在 `%LOCALAPPDATA%` / `%APPDATA%` / `%TEMP%` 下 | 警告："可能被清理软件删除，确定要用吗？" |
| 在系统盘根目录（`C:\`） | 拒绝 |
| 在 `C:\Program Files` / `C:\Windows` | 拒绝 |
| 在已知网盘同步目录下 | 警告 + 说明 SQLite 损坏风险 |
| 在可移动盘上 | 警告："拔掉后无法使用" |
| 目录不存在 | 创建 |

### 路径本身的存储与恢复

**配置存 `%APPDATA%\神算子\config.json`**——这是**配置**，不是数据。被清了只丢"上次选的路径"，不丢经营数据。

**数据目录里放标记文件 `.shensuanzi-data`**（内容：schema version + 创建时间）。

**恢复逻辑**：

```
启动 → 读 config.json
  ├─ 有路径 → 直接打开
  └─ 没路径（首次 或 配置被清）→ 弹向导
       用户选了某个目录后
         ├─ 目录里有 .shensuanzi-data → 直接复用
         └─ 目录为空 → 初始化
```

这样即使 `%APPDATA%` 被 Nova 干掉，用户重选原目录，数据立刻回来——**不需要用户记住路径**。

**迁移功能**（设置里）：改路径时把数据 + 备份一起搬，不是只改配置。

### 备份位置

**放在数据目录的兄弟目录**，不是子目录：

```
D:\神算子数据\         ← 数据库
D:\神算子备份\         ← 每日备份
```

为什么不放子目录：用户想"把数据拷到 U 盘"时，如果备份在数据里面，会形成"备份里包含备份"的递归。分开后两个目录都很直观。

**这也顺带回答了你的原问题**：备份打包的逻辑只依赖"数据目录的父目录"，与 `%LOCALAPPDATA%` 完全解耦。

## 二、UI 原则：清晰优先于美观，但要"看起来不像上个世纪"

你说的用户画像准确。加两条补充：

### 补充 1：中老年用户不是"不会用"，是"不愿意试"

他们能学会任何东西，但**不会主动探索**。任何"这个按钮点一下试试"的设计，在他们那里等于"永远不点"。

**推论**：

| 常见设计 | 对中老年用户 |
|---|---|
| 图标按钮（无文字） | 不认识 → 不用 |
| 悬浮提示（hover） | 不会悬停 → 看不到 |
| 汉堡菜单 ☰ | 不懂 → 找不到 |
| 隐藏的右键菜单 | 不会右键 → 功能不存在 |
| 快捷键 | 不记 → 等于没有 |

**原则：所有功能必须有常驻可见的入口 + 文字标签**。图标可以加，但文字必须在。

### 补充 2：中老年用户的"错误"比你想象的更严重

他们错一次，会认为"这软件有问题"，然后不再用。

**推论**：

| 设计 | 目的 |
|---|---|
| 所有删除操作二次确认 | 防误删 |
| 单号、金额、数量输入带即时校验 | 防误输 |
| 开完单显示"本次已保存，单号 XX" | 让用户确信 |
| 允许撤销（尤其是撤单） | 给他们"我错了也能补救"的信心 |
| 错误信息说"怎么办"，不说"哪里错了" | ❌"外键约束失败" ✅"这个商品还没建过，请先到商品页添加" |

### 视觉基调

**"清晰明了、引导明确"翻译成具体数字**：

| 项 | 值 |
|---|---|
| 基础字号 | 16px（默认 125% 缩放） |
| 行高 | 1.6 |
| 按钮最小点击区 | 44×44 px |
| 表格行高 | 48 px |
| 主要文字对比度 | ≥ 7:1（WCAG AAA） |
| 次要文字对比度 | ≥ 4.5:1 |
| 主色 | 一个，不要多 |
| 动画 | 只在"操作成功"时用，≤ 200ms |
| 阴影/渐变 | 不用 |
| 圆角 | 统一 4-6px，不要更大 |

**配色建议**：避免"纯白 + 纯黑"的刺眼，用 `#FAFAFA` 背景 + `#1A1A1A` 文字。主色用低饱和蓝或绿，**不要红**（红色只留给错误和告警）。

### 缩放机制

**不要用 `Cmd/Ctrl + 滚轮`**：中老年用户不会发现。

**放设置里 + 独立入口**：

```
设置 > 显示 > 界面缩放

  [ - ]   125%   [ + ]
  ─────────────────
  ○ 小    100%
  ● 标准  125%    ← 默认
  ○ 大    150%
  ○ 特大  175%
  ○ 超大  200%
```

**实现建议**：

- 用 `MediaQuery` 的 `textScaler` 全局缩放
- 所有尺寸用相对单位（不写死 `fontSize: 14`，写 `fontSize: 14 * scale`）
- 缩放变化**实时预览**，不是"重启后生效"
- 缩放值存 `config.json`（不是数据库——这是设备偏好，不是业务数据）

**默认为什么是 125%**：Windows 显示设置里，1080p 显示器很多用户就调到了 125%。神算子默认跟上，用户第一眼看到的就是"合适的大小"，不需要再调。

### 一个不能省的细节：数字输入的键盘

中老年用户在做零售/批发时，**输入数量、单价、金额是最高频动作**。

- 数量、金额输入框：**默认弹出数字键盘**（Windows 上是触摸键盘 / Android 上是数字键盘）
- 支持"回车确认"，不用鼠标点下一格
- 输入 `1.5` 和 `1.50` 应该等价（自动规范化到分）

Android 端尤其要注意：默认弹出的是带字母的键盘，用户要先切到数字，**这是纯粹的摩擦**。用 `keyboardType: TextInputType.numberWithOptions(decimal: true)` 能省掉这一步。

### 一个你可能想砍、但建议保留的：欢迎向导

首次启动的 5 步向导，看着像"多余"，但对你这个用户群：

```
1. 欢迎        "神算子会帮你记库存、算账"
2. 数据位置     "你的数据放在你自己的电脑里"
3. 商店信息     "店名（可跳过）"
4. 账户设置     默认勾选 现金 / 微信 / 支付宝
5. 完成         "按 F1 随时看帮助"
```

**第 2 步是关键**——它给用户一个**明确的承诺**："数据在你自己的电脑里，不在我的服务器上"。这正是你开源 + 本地部署的核心卖点，但**用户不会从 README 里读到**，必须在第一次打开软件时看到。

## 三、顺序建议：Windows 先，Android 后

Android 的同步依赖 Windows 主机已经跑起来。Windows 端做完了，Android 才有东西连。

**Windows UI 的最小闭环**：

```
商品建档 → 采购入库 → 库存查询 → 销售开单 → 收款
```

**这一步跑通，加上已有的 SyncServer，Android 端就有了可测的服务端**。
