## 第二项：§AF 6 处类推 + `Agents.md`

### 反向修正：**同意方向，但正则要补 `+`**

**`csvEscape` 纯数字放行是对的**。理由准确：

- 会计求和时，"收款 -500" 如果是文本，求和会跳过——**用户看不出来**
- `-12.34` 是合法数字字面量，**不是注入向量**
- 收窄防护不削弱真实防护

**但正则 `^-?\d+(\.\d+)?$` 会拒绝 `+12.34`**——`+12.34` 在 Excel 里也是合法数字。虽然神算子目前不产生带 `+` 的数字，但：

1. **往来方余额可能拆列后不再带负号**，但**流水不会**
2. 万一将来某处输出带 `+`（比如"调整"类单据），会变成文本

**建议**：正则改为 `^[+-]?\d+(\.\d+)?$`。

**另一个真实风险**：**金额格式化不能带千分位**。

- `formatAmount` → `1234.56` ✅ 是数字
- `formatGroupedAmount` → `1,234.56` ❌ 不是数字，且逗号会触发 CSV 转义变文本

**导出的金额必须用不带千分位的格式**。这一条要写进 `csv.dart` 的注释——与 `Money.formatGrouped` 是两个用途，别混用。

**顺序也要写清**（影响正确性）：

```dart
String csvEscape(String s) {
  // 1. 纯数字字面量直接返回（不引号、不加 '）
  if (RegExp(r'^[+-]?\d+(\.\d+)?$').hasMatch(s)) return s;
  // 2. 注入防护（首字符 = + - @，此处已排除纯数字）
  var safe = '=+-@'.contains(s[0]) ? "'$s" : s;
  // 3. CSV 转义
  if (safe.contains(',') || safe.contains('"') || safe.contains('\n')) {
    return '"${safe.replaceAll('"', '""')}"';
  }
  return safe;
}
```

**顺序错了（先加 `'` 后判数字）就失效**。
