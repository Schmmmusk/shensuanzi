# 裁定：先做核心闭环，但先抽一个"数据目录对话框"

## 一、向导的 5 步不是一回事

把向导拆开看，会发现内部硬度差异极大：

| 步骤 | 是不是硬依赖 | 能否后补 |
|---|---|---|
| 1. 欢迎 | 否 | 完全可后补 |
| 2. **数据位置** | **是** | **必须先有** |
| 3. 商店信息 | 否 | 可后补 |
| 4. 账户设置 | 否 | 可后补（有默认值） |
| 5. 完成 | 否 | 完全可后补 |

**只有第 2 步是硬依赖**——没有它，数据库不知道放哪，程序根本起不来。

所以真正的问题不是"向导 vs 闭环"，而是"**第 2 步是否要包装成向导**"。

## 二、我的建议：第 2 步不包装成向导

**用最朴素的方式满足第 2 步**：首次启动，弹一个标准的"选择数据文件夹"对话框。

```
┌────────────────────────────────────┐
│  选择数据存放位置                   │
│                                    │
│  建议放在非系统盘：                 │
│  D:\神算子数据\                     │
│                                    │
│        [ 更改 ]  [ 开始使用 ]       │
└────────────────────────────────────┘
```

**不做**：欢迎语、店名输入、账户预设、完成页。
**做**：默认路径 + 校验 + 创建标记文件。

这样第 1 天就能直接进入核心闭环。向导的其余 4 步，等核心功能全定了再补——**到那时你才知道向导该引导用户去哪里**。

## 三、为什么顺序是"闭环 → 向导"

三个理由，按重要性排：

**1. 向导的设计依赖核心功能的行为**

向导第 3 步会问"你的店名"，第 4 步会预设账户——但这两个字段在开单页怎么用、账户类型有哪些、默认账户是哪个，**要开单页真做出来才知道**。

现在写向导，等于**先冻结一套还没有使用场景约束的决策**。做完闭环再写向导，是在"已知用户会怎么用"的前提下写引导。

**2. 向导是一次性消耗品，闭环是天天用的**

用户看 5 分钟向导，用 5 年开单页。

开单页的每个摩擦（比如"数量输入要鼠标点三次"）会被重复上千次；向导的每个瑕疵只被看到一次。**资源应该压在重复使用的界面上**。

**3. 向导容易变成拖延症**

做"欢迎页的配色"比做"采购入库的分派逻辑"舒服得多，因为没有对错、没有边界、可以无限打磨。**先做闭环是一种防拖延的纪律**。

## 四、但有一个例外：向导第 2 步要现在就做对

数据目录对话框虽然只有一屏，但**它的决策一旦错，用户数据就危险**（`%LOCALAPPDATA%` 被清、OneDrive 冲突、U 盘拔盘）。这个对话框的校验逻辑、默认路径选择、标记文件，**必须第一时间做对，不能"先凑合再改"**——因为一旦用户真的开始录入数据，改数据目录的代价就大了。

具体说，第 1 天要做的是：

```
DataDirectory 服务（core 或 windows_app 里）
  ├─ resolveDefault()      → D:\神算子数据\ 或 C:\Users\<你>\神算子数据\
  ├─ validate(path)        → 返回 ok / warn(reason) / reject(reason)
  ├─ ensureInitialized()   → 创建目录 + 写 .shensuanzi-data
  └─ isShensuanziDir(path) → 检查标记文件
```

加一个最小的"选择文件夹"对话框 UI。**不做漂亮，够用就行**。

## 五、执行顺序

| 天 | 任务 |
|---|---|
| 1 | `DataDirectory` 服务 + 数据目录对话框 + 空主界面 |
| 2-3 | 商品建档（列表 + 编辑 + 条码） |
| 4-5 | 采购入库（开单页 + 立即付款） |
| 6 | 库存查询 |
| 7-8 | 销售开单（开单页 + 立即收款 + 赊账） |
| 9 | 收款（核销页） |
| 10 | **回补向导 1 / 3 / 4 / 5 步** |
| 11 | 备份打包 + 设置页（含缩放） |
| 12 | 端到端 + 打包 |

**第 10 天回补向导时，把 5 步模态向导简化为**：

```
首启：
  数据目录对话框（已实现）
  → 主界面 + 一个欢迎浮层
      ┌──────────────────────────┐
      │ 欢迎使用神算子            │
      │ 你的数据存在：            │
      │ D:\神算子数据\            │
      │ [ 先去建个商品 ]  [ 跳过 ]│
      └──────────────────────────┘
```

**不做 5 步模态向导**。理由：
- 中老年用户对"被要求一步步操作"敏感，一屏浮层更友好
- 店名 / 账户预设可以放在设置页里，用户想改随时改
- 模态向导会**挡住用户"先随便看看"的冲动**——而这个冲动是最宝贵的

## 六、一句话

**先做能用，再做引导。** 但"数据目录"这一件事不能等——它不是引导，它是启动前提。所以：第 1 天做数据目录对话框（唯一必须的向导步骤），第 2-9 天做核心闭环，第 10 天回补其余引导。
