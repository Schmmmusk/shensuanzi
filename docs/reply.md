## 二、优先级排序的 3 处调整

### 1. M04 必须从 P2 提到 P1

**理由：这是信任问题，不是体验问题。**

未配对却显示「已同步」——用户会以为：

- 「手机和电脑连上了」（实际没配对）
- 「我刚开的单已经传到电脑了」（实际还在本地队列）
- 直到某天发现电脑上根本没有这张单

**这直接摧毁用户对「同步」这个功能的信任。** 和 BUG-04（退货后原单状态不同步）属于同一类：**用户看到的和实际不一致**。

**建议动作：**

> M04 提到 P1，与 M15 同批。修复极简单：`mobile_shell.dart:308` 的判定加上「已配对 + 已首拉」前置条件，未配对时显示「尚未连接主机」。

### 2. M16 从 P2 提到 P2 首位（或 P1）

**理由：用户被彻底困住，和 BUG-03 同类。**

镜像打不开 → 进框架异常页 → 无重试、无导航、无出路。**只有重启才能恢复，而且重启也可能恢复不了**（如果镜像真的坏了）。

**再加上一个架构判断：** `openMirror()` 在 **build 期调用**本身就是反模式——build 应该只做纯布局，I/O 应该在 `_prepare` 阶段完成。

**建议动作：**

> M16 提到 P2 首位（如果 M04 提 P1，M16 就应该紧接 P1 之后）。修复要**两步**：
> 1. 把 `openMirror()` 从 build 期移到 `_prepareMobile`（架构修复）
> 2. `_prepareMobile` 捕获镜像打开失败 → 给中文错误页 + 重试按钮（体验修复）
>
> 只做第 2 步是补丁，做第 1+2 步才是修复。

### 3. M13 从 P2 提到 P1 或 P2 首位

**理由：这不是视觉问题，是功能不可用。**

小屏 + 超大字号下，保存按钮越出屏幕、大金额合计截断——**用户点不到保存、看不清金额**。这不是「难看」，是「用不了」。

**建议动作：**

> M13 提到 P2 首位。修复是 Row 换 Wrap + 金额 `Flexible`。与 §CH 的 B1′ 窄屏适配合批——已经计划做了，顺手一起。

## 三、批次合并建议

现在报告把 M09/M11/M12 分在了两组，M08/M14 分在了两组。**按根因看，应该合并：**

| 批次 | 内容 | 当前分组 | 建议 |
|---|---|---|---|
| **草稿保护** | M09（返回丢）+ M11（备注不触发确认）+ M12（让价不重算） | P2 / P2 / P2 分散 | **合并为一批**——都是「用户输入和系统状态不一致」 |
| **库存离线视图** | M08（开单页）+ M14（库存页） | P3 / P2 分散 | **合并为一批**——都是「库存视图不认离线影响」，共用 `stockViewOf` |
| **错误提示友好化** | M03（相机）+ M15（SQL 泄露）+ M16（无重试页） | P3 / P1 / P2 分散 | **合并为一批**——都是「异常没分类、直接甩给用户」 |

**合并的好处：** 一次改完一个主题，一次回归一个主题。分散改会重复打开同一批文件，还容易改漏。
