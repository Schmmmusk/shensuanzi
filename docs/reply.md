# §AG + §AH 审查意见

## 总评

**§AG 的三个发现是真的、阻断项清单是完整的、最小定义是对的**。**§AH 的"Android 第一天不在 Android"是这份提案最重要的一句话**——它把 Android 的工程量砍到一半。

但有 **2 处裁定要改**（AG-1、AG-6）、**3 处要补**（AG 缺图标、AG 缺首次运行、AH-B 缺配对体验），另有 **8 项遗漏**——其中 **4 项是"用户第一天就会撞到"**。

---

## 一、§AG 逐条审查

### 发现 1 / 2 / 3 ✅

三条发现都是**事实核对出来的，不是估的**。发现 2（同步未接通）尤其重要——它把 §AH 从"做 Android"变成了"先接主机"。

### 最小定义 ✅ 但**漏了一句**

"一台干净的 Windows 电脑，只放产物目录"——**"产物目录"这个词要先定义**。

用户拿到的是什么？两种可能：
- **便携 zip**：解压后有一个文件夹，里面是 `shensuanzi.exe` + `data/` + 一堆 dll
- **安装包**：装到 `Program Files` 里

**AG-2 选便携 zip**，所以最小定义里的"产物目录"= **解压出来的那个文件夹**。这一点要在 README 里写明——用户不会自己想到"这个文件夹可以整个拷到 U 盘"。

### B1~B9 阻断项 ✅ 但 **B3 缺一块**

B3 只提了 `Runner.rc` 的属性。但**还有一个更显眼的东西没提**：

**应用图标**。

Flutter 默认模板的图标是蓝底 Flutter logo。用户拿到首发版，桌面上、任务栏上、Alt+Tab 里全是**Flutter 的 logo**——这比"公司名是 com.example"更直接地告诉用户"这是个没做完的东西"。

**补一条 B10：应用图标**。需要：
- Windows：`windows/runner/resources/app_icon.ico`（多分辨率 ico：16/32/48/64/128/256）
- Android：`android/app/src/main/res/mipmap-*/ic_launcher.png`（暂缓，随 Android 做）

**图标设计**：不需要美术功底——一个简单的字形（"神"或"算"）+ 一个背景色即可。**建议用系统字体渲一个**，不追求精致。**有**比**好**重要——**默认 Flutter logo 是明确不能留的**。

### AG-1 版本号 ⚠️ **建议改**

同意"对外首发号不能失信"。但 **`0.1.0` 是对机器说的，不是对用户说的**。

用户看到的应该是：
- **关于页**：`神算子 v0.1.0（内测版）`
- **exe 属性页**：`文件版本：0.1.0.1`
- **README**：`当前版本：0.1.0（第一个可部署版本）`

**关键**：如果只写 `v0.1.0`，中老年用户看到会想"这是不是试用版？会不会用几天就不能用了？"

**建议**：把"内测版"或"第一个可部署版本"这个限定词**写进关于页**。这不是美化，是**消除用户的疑虑**——`0.1.0` 对工程师是"早期"，对用户是"未完成"。

具体：
- `pubspec.yaml`: `0.1.0+1`
- `help_page.dart`: `v0.1.0（第一个可部署版本）`
- `Runner.rc`: `FileVersion` = `0.1.0.1`，`ProductVersion` = `0.1.0`

### AG-2 便携 zip ✅

同意。补一句：**zip 里要带一个 `使用说明.txt`**（不是 README.md）——中老年用户不会打开 `.md` 文件。

内容极简：
```
神算子 v0.1.0

1. 双击 shensuanzi.exe 启动
2. 第一次会问你把数据放在哪，建议选 D 盘
3. 数据在你自己电脑里，不会上传

遇到问题：见「帮助」页
```

**编码必须是 UTF-8 with BOM 或 GBK**——否则记事本打开乱码（2026 年的 Windows 记事本默认 UTF-8，但老用户可能用第三方编辑器）。

### AG-3 不签名 + 帮助页说明 ✅ 但**帮助页文案要具体**

"Windows 提示未知发布者怎么办"——这个标题不够。**具体步骤**：

> **为什么打开时弹出蓝色警告？**
>
> 这是 Windows 对"没用购买证书的软件"的默认提示，**不是病毒警告**。
>
> 解决方法：
> 1. 点「更多信息」
> 2. 点「仍要运行」
>
> 只需要做一次，以后不再提示。

**"只需要做一次"这句是关键**——它告诉用户这不是每次都要做的麻烦。

### AG-4 LICENSE + THIRD_PARTY ✅

同意。补一点：**THIRD_PARTY.md 要说明字体**。

Windows 上用的是 `Microsoft YaHei UI` 等系统字体——**不打包、不授权**，但要在声明里说清"本软件使用系统已安装字体，未内嵌任何字体文件"。否则审查者会问"你的字体授权呢？"。

### AG-5 最小日志 ✅ 但**位置和内容要再想**

同意"未捕获异常 + 启动失败时写日志"。但**位置要改**：

- ❌ `数据目录/神算子-日志.txt` —— 和数据混在一起，用户备份时会把它一起拷走
- ✅ **`%APPDATA%\神算子\日志\`** —— 和配置同处，都是"设备本地状态"

**理由**：数据目录是**经营数据**（用户会拷来拷去），日志是**设备状态**（换机器没必要带）。§O 已经定了"配置放 %APPDATA%"，日志跟配置走是同一个原则。

**内容**：
- 启动时间、版本号、操作系统版本
- 未捕获异常的**完整堆栈**（Dart 的 `FlutterError.onError` + `runZonedGuarded`）
- **绝不记经营数据**（商品名 / 金额 / 往来方）—— 这条要写成注释

**格式**：纯文本，每行一条，**追加不轮转**。**不加时间戳格式化库**——`DateTime.now().toIso8601String()` 够了。

### AG-6 同步入口 ⚠️ **建议改：显示但禁用**

原提案说"**v1 隐藏**（不显示配对 / 同步菜单）"。**我建议改为：显示但禁用 + 说明**。

理由：

| 方案 | 用户行为 |
|---|---|
| **隐藏** | 用户不会知道有这个功能；将来出来时会想"之前怎么没有？" |
| **禁用 + 说明** | 用户看到"多设备同步（开发中）"，知道**将来有**，也**不用现在找** |

**这更符合 §AD 的"入口文案首次/再次"精神**——**让用户知道软件在往哪走**，比"假装这个功能不存在"更好。

**具体**：设置页加一行灰字（不是按钮）：

```
多设备同步（手机/平板）      开发中
```

**一个灰色标签比"没有这一行"更有信息量**。

### AG-7 文件属性 ✅ 但 **CompanyName 我给个建议**

`CompanyName` / `LegalCopyright`——你说"需要我给"。**我给一个建议**：

- **如果是以个人名义发布**：`CompanyName` = 你的名字或昵称，`LegalCopyright` = `Copyright (C) 2026 <你的名字>`
- **如果是匿名发布**：`CompanyName` = `神算子项目`，`LegalCopyright` = `Copyright (C) 2026 神算子贡献者`

**第二种更常见**——开源项目作者常用"项目名"而不是真名。**个人名义发布会让支持请求找上门**，匿名发布可以让支持走 GitHub Issues。

**推荐第二种**。

### AG-8 README 重写 ✅ 但**范围要明确**

"进度表整段重写"——**对**。但**不要重写成"未来路线图"**。

README 的进度表应该**只讲现状**：
- ✅ 已实现：商品 / 采购 / 销售 / 库存 / 往来 / 备份 / 导出 / 期初录入
- 🚧 开发中：多设备同步 / 收欠款 / 退货 / 送货
- 📋 计划：Android 客户端 / 打印

**不要写"v1.1 会做什么"**——那是承诺，不是现状。路线图放在 `docs/` 里，README 保持"**现在是什么**"。

## 二、§AH 逐条审查

### "Android 第一天不在 Android" ✅✅✅

**这是整份提案最有价值的一句话**。

它把 Android 的工程量**砍到一半**——因为 `SyncClient` 已就绪、`host` 已就绪，**缺的只是"接进桌面应用 + UI + 服务开关"**。

**AH-A 能独立验收**——浏览器/curl 就能测。这个判断**让 Windows 首发和 Android 解耦**，非常干净。

### AH-A / AH-B / AH-C 三阶段 ✅

同意。

### AH-1 包名 ✅

`com.example.shensuanzi` 必须换。**建议用 `com.shensuanzi.app`**（不需要域名反写——如果你没有域名的话）。或者用一个你控制的域名。

### AH-2 minSdk 24 ✅

同意。**补一点**：`compileSdk` / `targetSdk` 用最新（Flutter 默认给的），**不要为了兼容旧机降 target**——那是自找麻烦。

### AH-3 APK 直发 ✅

同意。**补一点**：APK 也要**改名**——不要叫 `app-release.apk`，叫 `神算子-v0.1.0.apk`（或者带日期的）。用户下载下来看到"app-release"会困惑。

### AH-4 mobile_scanner ✅

同意。**补一点**：需要在 `AndroidManifest.xml` 声明 `CAMERA` 权限，**并且在应用内请求权限时给出理由**（"扫码配对需要用到相机"）——否则用户会拒绝。

### AH-5 手机版 shell ✅ **这是最重要的技术裁定**

我完全同意：**220px 左侧导航在手机上不可用**。

但**要明确一点**：这**不是**"换皮"，是**新增一套摆放**。

具体：
- **手机端**：底部导航栏（5 个入口：概览 / 开单 / 库存 / 往来 / 我的）
- **平板端**：可以沿用桌面 shell 或做中间形态（**v1 不做，用手机 shell 兜底**）
- **路由结构**：`Platform.isAndroid ? MobileShell() : DesktopShell()`

**关键**：这个判断要**放在纯 Dart**——`ShellKind.of(platform)` 返回枚举，Flutter 只摆。

### AH-6 app 私有目录 ✅

同意。**补充说明**：Android 上用 `getApplicationSupportDirectory()`，数据在 `/data/data/com.shensuanzi.app/files/`。**用户看不到这个目录**（除非 root）——所以备份功能在 Android 上要**显式导出**（分享到微信/邮件），不能靠用户"自己去找文件"。

**这是一条要写进 v1.1 的待办**——v1 的 Android 只读不写（开单推给主机，数据不留在本地），所以**暂时不涉及备份**。

### AH-7 明文 HTTP 白名单 ✅

同意。**具体实现**：`res/xml/network_security_config.xml`：

```xml
<network-security-config>
  <domain-config cleartextTrafficPermitted="true">
    <domain includeSubdomains="true">192.168.0.0/16</domain>
    <domain includeSubdomains="true">10.0.0.0/8</domain>
    <domain includeSubdomains="true">172.16.0.0/12</domain>
  </domain-config>
</network-security-config>
```

⚠️ **注意**：`<domain>` 只接受**主机名**，不接受 CIDR。**实际写法**要用 `<base-config cleartextTrafficPermitted="true">` + 在应用层校验"必须是局域网 IP"。

**这是一个真实的坑**——写在提案里比实施时踩便宜。

### AH-8 冲突与队列 ✅

同意。**补一点**：三态提示要在**每一个页面都能看到**——不是只在设置页。**建议放在 AppBar 或底部状态条**：

```
[已同步] / [待同步 3 条] / [同步失败，点击查看]
```

**用户在任何页面都应该知道"我的数据有没有送到主机"**。

## 三、遗漏项（8 项）

### 遗漏 1：**AG 缺"首次运行"的体验设计** 🔴

用户拿到 zip → 解压 → 双击 exe → **会发生什么？**

- 数据目录对话框弹出 ✅ 已有
- **但用户不知道这是什么**——"我明明刚解压，怎么问我要放哪？"

**建议**：在数据目录对话框**顶部加一句**：

```
欢迎使用神算子

这是第一次启动。请告诉神算子把你的数据放在哪——
数据存在你自己电脑里，不会上传。
```

**"不会上传"这四个字**是用户第一个信任锚点，比任何功能都重要。

### 遗漏 2：**AG 缺 exe 的"首次运行"提示** 🔴

SmartScreen 警告出现后，用户点了"仍要运行" → **数据目录对话框弹出**。

**但对话框可能被 SmartScreen 抢焦点**——用户点了"仍要运行"后，对话框在**后面**，用户看不到。**这需要测试**。

**建议**：`app.dart` 里弹对话框前**先 `WidgetsBinding.instance.addPostFrameCallback`** 加一帧延迟——让 SmartScreen 完全关闭。

**如果还是被抢焦点**，加一个 `windowManager.toFront()` 调用（需要 `window_manager` 包——**这可能是第一个需要评估的额外依赖**）。

### 遗漏 3：**AG 缺 README 的"三分钟上手"** 🔴

README 现在的目标是"解释项目"，不是"告诉用户怎么用"。

**用户拿到 zip 后**：解压 → 找 README → **发现是一堆技术术语** → 放弃。

**建议**：README **顶部**加一段：

```
## 快速上手

1. 解压这个 zip 到任意文件夹
2. 双击 shensuanzi.exe
3. 选一个放数据的位置（建议 D 盘）
4. 开始用

详细说明见「帮助」页。
```

**技术内容全部下移**。

### 遗漏 4：**AH 缺"主机显示二维码"的 UI** 🔴

AH-A 说"配对码 / 二维码渲染"，但**没具体说 UI**。

**具体流程**：
1. 设置页 → 「多设备同步」→ 打开开关
2. **显示二维码**（含 IP + 端口 + 令牌）
3. 显示文字说明："用手机上的神算子扫这个码"
4. **二维码旁边显示**：`主机 IP：192.168.1.5 端口：17890`
5. 底部："扫码后手机就能看到这里的数据"

**"主机 IP + 端口"必须显示**——如果扫码失败，用户可以手动输入。**这是扫码的兜底**。

### 遗漏 5：**AH 缺"服务开关"的默认值** 🟡

`多设备同步` 开关**默认应该是关还是开**？

**建议默认关**。理由：
- 用户可能不想让局域网里的其他设备访问
- 打开时**要提示**："打开后，同一 WiFi 下的设备可以扫码连接"
- 这是一个**显式的用户动作**，不是默认行为

### 遗漏 6：**AH 缺"服务状态"的可视化** 🟡

服务开着但没人连、服务开着有人连着、服务崩了——**用户不知道**。

**建议**：设置页那一行显示：

```
多设备同步              已开启
  已连接设备：0 台
  [显示二维码]  [关闭服务]
```

**如果崩了**：

```
多设备同步              启动失败
  端口被占用或防火墙拦截
  [重试]  [查看帮助]
```

**"怎么办"写在领域层**（与 §AE 备份同款）。

### 遗漏 7：**AG 缺"卸载"的说明** 🟡

便携 zip 没有卸载程序。**用户可能问**："我怎么删除这个软件？"

**建议**：README 加一段：

```
## 怎么删除

1. 删除解压出来的文件夹（程序）
2. 如果也想删除数据，再去「设置」页看数据位置，手动删除那个文件夹
3. 备份文件夹在数据文件夹旁边，也可以一起删

⚠️ 删之前建议先把备份拷到 U 盘。
```

**"先拷备份"这句是关键**——用户可能一怒之下删了所有东西。

### 遗漏 8：**AH 缺"Android 版本兼容性检查"** 🟡

`/api/health` 现在返回 4 个键。**Android 首次连接时，要检查主机版本是否兼容**。

**建议**：`/api/health` 返回增加 `api_version`（整数）——Android 端启动时对比，不兼容就给明确提示："主机版本过旧，请更新主机"。

**这不是 v1 必须的**——但**现在加一个字段**比"将来改了要同时更新两端"便宜。

## 四、结论

**§AG 采纳 B1~B9，AG-2/AG-3/AG-4/AG-5/AG-7/AG-8 同意，AG-1 加限定词，AG-6 改为"显示但禁用"。**

| 项 | 修正 |
|---|---|
| AG-1 | 版本号对外加"（第一个可部署版本）"——消除"是不是试用版"的疑虑 |
| AG-6 | **显示但禁用**——让用户知道软件在往哪走 |
| B3 | 补 **B10：应用图标**——默认 Flutter logo 不能留 |
| AG-5 | 日志改到 `%APPDATA%\神算子\日志\`——与配置同处 |
| AG-8 | README **只写现状**，不写未来路线图 |

**§AH 采纳 AH-1~AH-8，补 4 项遗漏。**

| 项 | 修正 |
|---|---|
| AH-7 | `network_security_config` **不接受 CIDR**——实际要靠应用层校验 |
| AH-8 | 三态提示**放 AppBar / 底部状态条**，不只设置页 |
| AH-A | 补**二维码配对 UI 的具体流程**（含"主机 IP + 端口"的兜底显示） |
| AH-A | 补**服务开关默认关** + **服务状态可视化** |

**补充 8 项遗漏**，其中：
- 🔴 遗漏 1（首启文案）/ 2（SmartScreen 抢焦点）/ 3（README 快速上手）/ 4（配对 UI）**必须落地**
- 🟡 遗漏 5/6/7/8 建议落地

**核心判断**：

§AG 和 §AH 的**技术骨架都对**——B1~B9 完整、三阶段顺序对、"Android 第一天不在 Android"是关键洞察。

但**"用户的第一次接触"没有被设计**——首启文案、SmartScreen 后的对话框、README 的快速上手、配对的二维码 UI。**这些不是功能，是"用户会不会用起来"的问题**——与 `ui_principles.md` 的精神同源：**说清楚，不让用户猜**。

**"可落地生产环境"的本质不是"能跑"，是"用户第一次打开就知道怎么用、第二次打开还愿意打开"**。

---

**下一步建议**：

1. **今天**：用户终端跑 `flutter build windows --release`，拿到 `Release/` 真实清单
2. **然后用 §AG 的裁定清单**逐个处理 B1~B10（含补的 B10 图标）
3. **README 重写**（AG-8 + 遗漏 3）
4. **首发验证**：一台干净电脑（或虚拟机）走一遍完整闭环
5. **首发之后**：开 AH-A（Windows 侧 host 接通）
