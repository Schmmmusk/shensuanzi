## 一、折扣抹零：移出「有意识不做」✅，但这是**范围扩大**不是措辞同步

### 为什么必须移出

冲突是真的：`§AJ` 的 `discount_amount` 进 v3 计划 ⇒ **这就是"做"**，与「有意识不做」直接矛盾。**后出裁定覆盖先前，但旧表述没清算**——5 处旧表述会继续误导。

### 但要精确化一处

采纳 `A1 + B2 + discount_amount` 之后，**原 4丙「摊到最后一行、不新增持久化字段」已经不成立**——4丙 是"不改 schema"的方案，现在 schema 要改了，**4丙 被替代**。

**实质变化**：

| 层 | 4丙（旧裁定） | A1+B2（新方案） |
|---|---|---|
| Schema | 无新字段 | **加 `discount_amount`** |
| UI | 录入辅助 | **直接录入让价** |
| 打印/详情 | 显示"含让价" | 显示"让价 -¥0.20" |
| 单价 | 最后一行被改 | **保持档价**（更干净） |

⇒ **「折扣抹零」从"不做"变成"v1 就做"**。这是**首发范围扩大**，需要：
- 重估工期（+0.5 到 1 天：UI + 测试 + 手册）
- 在 `§AR·一` 加一行（批次 3：折扣抹零）
- **不混进 1b**（1b 是送货；这个属于 v3 批次）

### 补一条 `discount_amount` 的语义

- 单位：**分**（与 `amount` / `unit_price` 口径一致）
- 符号：**正数**（表示"让掉多少"）；`amount = qty × price − discount_amount`
- 约束：`0 ≤ discount_amount ≤ qty × price`（不让"负商品"）
- 默认：**0**（不是 null —— 老行 `ALTER ADD` 自动为 0，语义与"无让价"一致）

**不采纳** `entry_discount` 的表述——「让价」这个词在 UI 上更亲切（与 `ui_principles §五`「说怎么办」同源）。

## 二、DocumentDraft 重构：**开**，但**判据要加一条**

### 用户判断对的部分

- **触发条件已满足** ✅（1b 出了第三份）
- **排在 1b 复跑之后** ✅ —— 理由对：三份都稳定时才看得清抽象形状；混进功能批次会让 review 变难
- **"抽"的时机** ✅ —— 别等太久，否则三份会继续各自演化

### 补一条判据

**「三份稳定」= 至少一周没动**。理由：

> 刚做完 1b，`DeliveryDraft` 是**新代码**，它的 API 形状还没被 bug 修复打磨过。
> 现在抽，会把「新增的漂移」也一起冻结进基类。

**具体判据**：
- 1b 复跑通过 ✅
- **其后至少一周**，三份 `*_draft.dart` 都无实质性修改
- 三份的**公开 API**（构造参数、getter 名、`validate()` 签名）已经**字形一致**

### 抽的时候：**共享测试套 > 共享基类**

这是关键。**抽象的价值在"行为一致"，不在"代码复用"**。所以：

| 做法 | 收益 |
|---|---|
| ❌ 只抽基类 | 代码短了，但三份的**行为**还是可能分叉（各自的 `validate()` 覆写） |
| ✅ 抽基类 **+ 参数化测试** | 同一套测试跑三遍（传入三种 Draft 构造函数）⇒ **行为一致被门禁守住** |

**参数化测试**举例：

```dart
for (final factory in [PurchaseDraft.new, SaleDraft.new, DeliveryDraft.new]) {
  test('空行报行级错误', () { ... });
  test('同商品不重复', () { ... });
}
```

**落点**：`test/support/document_draft_cases.dart`（新），三份测试各 import 它。

### 顺带一条：抽的时候**别把文档行为也一起抽**

比如"保存后保留供应商与日期"——**采购保留、销售也保留、送货要不要保留？** 这是**业务问题**，不是**抽象问题**。抽基类时**只抽结构**（行 / 付款 / 日期），**行为差异各留各的**。

## 三、import_guard 扩查相对 import：**采纳**，但**方法要改**

### 用户的判断对

- **假绿是真问题** ✅ —— `app_shell.dart` 漏 `import 'delivery_page.dart'` 没被抓到，报「0 处」是**假绿**
- **纯 Dart、可跑可验** ✅
- **必须做反向验证** ✅ —— 这条**最重要**

### 但「用正则」**不行**，三个理由

| 坑 | 后果 |
|---|---|
| **注释里的 `// import 'foo.dart'`** | 正则误报 |
| **字符串里的 `'foo.dart'`** | 同上 |
| **`as` 前缀**（`import 'foo.dart' as f;`） | `f.Foo` 不在正则范围，误报 |

**解法**：**复用已有的「Dart 源码状态机」**——`import_guard.dart` 现在**已经有**去注释/去字符串的实现（用于读桶文件 `show` 子句），这次**扩它的用法**，不重新写正则。

### 三条约束（v1 范围）

1. **只查无前缀导入**（`import 'foo.dart';`）—— `as f;` 的记在案，暂不支持
2. **接受假阳性** —— 本地变量遮蔽类名会误报，**宁多报不假绿**
3. **反向验证必须做** —— 改完后**故意摘掉一处相对 import**，确认它**会报**；报告里贴出「改坏前 → 0 处 / 改坏后 → 1 处」的对照

### 覆盖范围：`lib/` + `test/` 都要

- 之前 `import_guard` 的桶文件覆盖**已经覆盖了 `test/`**（`_ProductPickerSheet` 那次假绿就在 `test/`）
- 这次的相对 import 假绿在 **`lib/`**（`app_shell.dart`）
- **两处都要**，不能只扩一处

### 一个额外收益

扩完后，`import_guard` 就从「查桶导入」升级为「**查所有跨文件符号引用**」——**这是根层唯一能自跑的静态门禁**，它的价值会显著提升。
