看完截图和最新方案后，我的总体思路是：

**重新清点要从“填一张表”变成“逐件核对库存”；商品建档要从“填写一堆字段”变成“按照建档顺序逐步提供信息”。**

两者都应该减少用户思考操作规则的负担，但不能为了简洁而隐藏重要信息。

## **一、重新清点：让用户一眼看懂“账面多少、实际多少、差多少”**

*我最推荐优先设计的界面*

现在的界面有几个特点：

- 顶部说明较长，且两段文字承担了很多解释任务。
- 每行只有商品选择、数量输入、删除按钮。
- 当前账面数量和实时差额在商品选中后显示在下一行。
- 数量输入框没有明确使用“实际数量”作为字段名称。

其实原来的语义设计很好，我不建议推翻它。特别是以下规则必须保留：

1. 输入的是盘点后的实际数量，而不是新进货数量。
2. 重复录入同一商品，是将库存调整为新的实际数量，不是累加。
3. 0 是合法数量，表示已经卖光。
4. 空行忽略，同一个商品不能重复出现。
5. 盘点成本按现有规则处理，不能让用户误以为这次盘点会补录采购成本。

这些已经写进 `StocktakeDraft`，应当继续由 core 负责，而不是交给 UI 自行实现。

### **我的建议：每件商品使用一张独立的盘点卡片**

可以考虑这样的形态：

**可口可乐 500ml**

商品 P00001

当前账面库存

# **24 瓶**

实际库存

# **36 瓶**

盘点结果

# **将增加 12 瓶**

以本次填写的实际数量为准

实际数量（瓶）

### **36**

瓶

删除这一行

示意布局，非现有功能。

这里最重要的是：**把账面库存、实际库存和差额放在同一张卡片中。**

用户不需要反复阅读页面顶部的说明，也不需要自己拿计算器算差额。

### **多单位支持可以成为这次重做的核心价值**

比如商品档案已经配置：

- 最小单位：瓶
- 包装单位：箱
- 1 箱 = 24 瓶

那么盘点时可以显示：

**可口可乐 500ml**

当前账面库存：24 瓶

实际数量

# **2**

录入单位

# **箱 ▾**

**换算结果**

# **2 箱 = 48 瓶**

**将增加 24 瓶**

这会比让用户先换算成瓶、再填写实际数量自然得多。

不过，这里有个需要特别注意的技术问题：

目前 `StocktakeLineDraft` 只有 `quantity` 字符串，而 `DocumentLine` 的 `stocktake` 数量语义是最小单位下的实际数量。要支持按箱录入，不能只把开单页的输入框复制过来，还必须让盘点草稿能够保存录入数量和单位，并通过共享的纯 Dart 换算逻辑得到最小单位实际数量。

**换算由公共逻辑完成，库存差额仍由现有规则引擎计算。** Windows 直连和 Android 提交路径都必须遵守同一口径。

这也正好解释了为什么提案要求先抽出共享 `line_row.dart`，再给盘点页使用。

### **页面顶部也建议调整**

现在的两段解释可以精简为一张常驻说明卡：

**请填写店里现在实际有多少**

不是新进了多少。同一种商品再次清点，会将库存改成这次填写的数量。

卖光了填 0。期初成本按 0 记，之后正常采购会逐步校准成本。

保存按钮可以改成“核对并记入库存”，原有确认弹窗继续保留，让用户有最后一次检查机会。

还有一个小建议：目前截图中的删除操作只有一个 `×`，我倾向于改成文字明确的“删除这一行”，或者至少保留图标并配上清楚的文字标签。项目的用户群体不应该被迫猜图标是什么意思。

## **二、商品新增：把建档过程分成三个容易理解的区域**

建议保留现有字段，重新组织层次

从截图看，我认为当前表单最大的问题并不是字段数量特别多，而是：

- 常用单位 chips 占据了不少纵向空间；
- 进价、安全库存、包装说明、包装换算、条码挤在同一段；
- 包装说明和包装换算容易让人混淆；
- 条码位于较靠后的区域，用户很容易忽略；
- 用户还要依赖底部的“往下还有”提示发现未显示内容。

我的建议是将表单划分为三个区域。

### **1. 基本资料：先让用户把商品建起来**

**一、基本资料**

**商品名称**

**\***

例如：红富士苹果

\*\*单位 \*\*\*

瓶

\*\*售价 \*\*\*

5.00 元

常用单位：件 · 个 · 斤 · 公斤 · 瓶 · 包 · 袋 · 更多单位

这里有两个细节：

第一，必填字段明确标红色星号，符合现有 `ui_principles.md` 的要求。

第二，单位旁边保留一句简短解释：

> 单位填最小的售卖单位，例如按箱进、按瓶卖，就填瓶。

不必像现在那样用一整段大文字解释包装单位。

### **2. 经营信息：不要把重要字段藏起来**

**二、经营信息**

**进价**

3.50 元

不清楚可以先留空

**安全库存**

10

低于这个数量时提醒

**商品条码**

扫描或输入条码

没有条码可以留空；有条码建议现在录入。

这里我有一个不同于提案 §八的建议：

**进价、安全库存、条码这三个字段，不要全部改成勾选后才出现。**

原因很明确：`ProductDraft` 的设计注释已经说明：

- 进价隐藏了，用户可能永远不会知道毛利需要它；
- 安全库存隐藏了，用户可能永远不会设置补货提醒；
- 条码补录成本高于第一次录入。

所以它们可以标记为选填，但不能让用户不知道它们存在。

至于包装信息，我认为适合折叠，因为它确实不是每种商品都需要。

### **3. 包装信息：必须把“备注”和“换算”区分开**

这是现有界面一个容易引发误解的地方。

项目实际上有两套包装信息：

| 字段                                 | 作用                       |
| ---------------------------------- | ------------------------ |
| 包装说明 `packageNote`                 | 纯备注，例如“1 箱 = 48 瓶”，不参与计算 |
| 包装单位 `packageUnit` + `packageSize` | 真正的换算数据，会影响开单单位换算        |

我建议界面这样组织：

**三、包装信息**

选填

**包装说明**

例如：1 箱 = 48 瓶

只是给人看的备注，不影响计算。

**启用包装换算**

按箱、包等较大单位录入时，自动换算成最小单位。

展开以后才显示包装单位和换算数量两个输入框。

但有一个必须遵守的细节：编辑已有商品时，如果已经配置过包装换算，就应自动展开并回填原值，不能因为折叠而让用户误以为没有配置。

### **另外，有一个现有界面的小问题值得顺手解决**

我注意到你提供的商品新增截图里，进价和安全库存其实已经出现在当前可见区域，但底部固定提示仍然写：

> 往下还有：进价 · 安全库存 · 条码

这条提示与当前屏幕内容不一致。

我查了当前 `product_form_dialog.dart`，它的提示文字确实是固定写死的。建议将来改为动态显示真正尚未进入视口的字段，避免出现“明明已经看见了，却告诉我还在下面”的情况。

## **三、两处界面如何分批施工**

我建议把它们拆开，而不是一起交给 Agent。

| 优先级 | 工程            | 最重要的验收点           |
| --- | ------------- | ----------------- |
| 第一  | 重新清点卡片化 + 多单位 | 实际数量、单位换算、差额正确    |
| 第二  | 商品建档分区重做      | 重要字段始终可发现，包装信息不混淆 |

特别是重新清点，要先完善共享组件的设计与测试护栏，再改三大开单页和盘点页。

商品建档则要保留 `ProductDraft` 的纯 Dart 校验，不要让界面重构顺手修改业务校验逻辑。原有 `Key`、条码重复提示和保存失败时保留输入的行为也要继续守住。

测试至少覆盖 800×600、480×360 和 2 倍字号；还要测试商品已有包装配置时的编辑场景。

## **我的最终倾向**

这两处我会这样定设计方向：

**重新清点：卡片化、差额突出、支持按包装单位录入。**

**商品新增：三段式信息结构、重要字段始终可见、包装换算按需展开。**

我认为这比单纯把表单缩短、把按钮摆整齐更有意义。

因为它们最终解决的是两件事：一个让用户不容易把库存盘错，另一个让用户不容易漏掉商品建档的重要信息。

这才是神算子界面精修真正值得花时间的地方。🤓
